## 规格交付与阶段边界

本轮交付为规格文档；目录树中的生产文件是获批后待创建的清单，目前并未初始化工程。
本期实施目标分为“可运行的前端静态骨架”和“只含职责说明的后端结构”，两者不能混称为已实现的前后端应用。

目录、逐文件职责和本期静态函数草稿在[计划](plan.md)；业务文件只确定归属和职责，未来函数、字段及接口契约由各自功能规格确定。
本规格不扩展为订单管理、任务管理、下载、生成或 Worker 的实现规格。

### 本轮用户明确指令与审批边界

项目负责人在本次请求中明确要求：“本规格不涉及到测试的部分，例如后端接口暂时不实现，可以先略过测试的实现，前端先完成项目结构的静态界面即可”。

据此本规格不编写或执行自动化测试，不初始化测试框架和测试用例，采用[任务清单](tasks.md) 中的替代验证。
这是一项仅适用于本轮静态骨架的明确用户指令，优先于本地常规测试先行要求；不改写
[`AGENTS.md`](../../AGENTS.md)、[宪法](../../.specify/memory/constitution.md) 或[测试规则](../../docs/rules/testing.md) 的通用门禁。
测试阶段状态记为“本轮不适用”，不是“测试已通过”；不建立或索取一次没有实际测试阶段的测试审批。

三份核心规格及附属设计仍须由项目负责人明确批准，批准之前只修改文档；批准之后仅可实施该静态骨架范围。
新增业务、后台服务启动、中间件连接或接口能力必须另行准备规格并恢复常规测试先行与审批流程。

## 用户场景与验证

### 用户故事 1：访问静态应用并切换页面（P1）

使用者进入应用，看到左侧两个菜单项；切换时内容区显示对应页面名称，URL、选中菜单和标题保持同步。

**优先级原因**：形成后续业务开发共同使用的导航和布局。

**独立验证**：启动前端、切换页面、直接访问和刷新两条路由，确认内容和导航；验证编号见任务映射，不生成自动化测试。

**验收链接**：[`AC-041`](../../docs/product/acceptance-criteria.md#ac-041)、[`AC-057`](../../docs/product/acceptance-criteria.md#ac-057)、[`AC-059`](../../docs/product/acceptance-criteria.md#ac-059)。

### 用户故事 2：从清晰的结构开始后续功能（P1）

贡献者能够根据目录和文件职责找到前端入口、路由、布局、页面、功能模块、共享模块以及后端各层。
后续实现填入对应位置，不把业务逻辑混入导航或入口。

**优先级原因**：本轮主要交付是确定结构和文件用途。

**独立验证**：逐项对照计划目录与文件表，确认文件存在、占位注释和依赖方向；不启动后端。

**验收链接**：[`AC-058`](../../docs/product/acceptance-criteria.md#ac-058)。

### 用户故事 3：处理错误地址（P2）

误入不存在的地址时显示轻量 404，并可以返回订单管理。

**优先级原因**：完成基础路由边界，避免误入空白页；不增加第三个业务页面。

**独立验证**：打开未知路由、返回订单管理；核对导航选中状态。

**验收链接**：[`AC-029`](../../docs/product/acceptance-criteria.md#ac-029)、[`AC-041`](../../docs/product/acceptance-criteria.md#ac-041)。

### 边界情况

- `/` 使用替换历史的重定向进入 `/orders`；两个业务路由直接访问、刷新及浏览器前进后退均可用。
- 未知路由不选中任何业务菜单项；用 404 返回入口进入订单管理。
- 不接受 query 驱动业务查询，不读取客户信息或创建服务端状态；已接受 ADR 中关于筛选 query 的要求留到订单规格。
- 页面仅展示页面名称，不提供不可用的业务按钮、示例订单、伪造任务或模拟进度。
- 前端不导入占位模块，不发起业务网络请求；已有容器的运行状态不影响本轮启动。
- 缺少 DOM 根节点时给出清晰入口错误；业务页面渲染异常在布局内显示可恢复提示，不新增独立 500 页面。

## 需求

### 功能需求

- **FR-001**：前端使用已接受栈的基础部分，可独立安装、启动、类型检查、构建和预览。
- **FR-002**：左侧菜单固定包含“订单管理”和“任务管理”，页面主体分别显示同名文字。
- **FR-003**：使用已确认业务路径和根重定向，保留轻量 404；提供键盘可用的导航和清晰焦点。
- **FR-004**：目录、文件、职责和本期静态函数按计划确定；计划中标记“占位”的文件只保留中文职责说明。
- **FR-005**：后端按传输、应用、领域、端口和基础设施预留结构，本期不构建或启动 Java 服务。
- **FR-006**：后端入口、POM 和外部配置只标明未来用途；不放入假 Controller、假接口、启动失败的空壳服务或数据库迁移。
- **FR-007**：不引入后端连接、数据查询、导出、SSE、轮询、认证、容器编排、CI 或发布能力。
- **FR-008**：文档和占位文件不记录密码、客户数据或个人机器路径；本轮不读取或修改现有容器中的数据。

### 关键实体

仅存在静态导航配置和页面路径类型，定义见[计划](plan.md)。没有业务实体、数据库结构、消息或 API DTO 的本期定义，因此不生成 `data-model.md` 或 `contracts/`。

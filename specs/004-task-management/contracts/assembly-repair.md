## 触发与可观察结果

保留“先收集全部数据块，再装配Excel”的流程。在装配入口对全部预期分段、数据库登记和实际数据块文件完成对账；装配读取每块至EOF时继续核对，防止入口校验后文件再变化；最终候选Excel关闭后仍须完整校验，成功登记与采用前不得跳过。没有逐次SSE读盘或新增运行巡检，错误在上述装配边界发现。

发现缺失、损坏或登记不匹配时记录安全错误及修复原因；可修复的任务保持RUNNING，阶段进入CHECKING，完成整轮对账后先提交新的可信进度和REBUILDING，再在同一任务内自动重试。不能先提交FAILED再偷偷重开，也不要求用户重新创建任务。文件修复错误不是暂停失败。

验收关联：[装配对账](../../../docs/product/acceptance-criteria.md#ac-088)、[选择性重建](../../../docs/product/acceptance-criteria.md#ac-089)、[进度修正](../../../docs/product/acceptance-criteria.md#ac-090)、[重建提示](../../../docs/product/acceptance-criteria.md#ac-091)、[修复闭环](../../../docs/product/acceptance-criteria.md#sc-017)。

## 哪些文件可以复用

| 对象 | 创建者与位置（相对受控fileRoot） | 校验与复用 | 关闭／清理 |
| --- | --- | --- | --- |
| 原始数据块 | Worker收集服务；`tasks/{taskId}/data/{dataGeneration}/blocks/{blockId}.jsonl` | 文件、登记及分段清单完整匹配才保留；保留任意位置的匹配块，不局限于首个坏块之前 | 不覆盖原文件；替换用新blockId。旧登记与受保护引用保留，不因修复直接删除 |
| 数据块写入半成品 | 同目录`.jsonl.part` | 关闭、force、同卷原子移动后才登记；未登记文件不计进度 | 无引用且无有效执行后按既有清理许可与宽限清理 |
| POI工作文件 | SXSSF；`scratch/{processId}/{taskId}/{fence}-{owner}/{id}.tmp` | 不是登记的数据块，没有跨进程／跨Workbook恢复能力；不参与可信行数 | 每次装配退出时由Workbook.dispose/close释放；异常遗留按既有许可清理 |
| Excel候选文件 | 装配器；`tasks/{taskId}/attempts/{fence}-{owner}/staging/{artifactId}.xlsx.part` | 失败候选不可续写；新Workbook重放按序选择后的全部数据块 | 本次资源关闭后按受控候选处置／既有许可清理，不删READY或ADOPTED引用 |
| 正式产物 | 发布服务；`tasks/{taskId}/artifacts/{artifactId}.xlsx` | 沿用关闭、校验、force、原子发布、READY登记与成功采用 | 成功采用文件永久保留；发现已有READY损坏不能直接删除保护引用 |

临时文件“可信”指内容与已提交数据库基线一致，不是文件名正确或exists=true。字节数、SHA-256、行数、header、任务／配置身份、数据代次、sequence及游标区间均需核对。摘要保存在数据库不等于当前磁盘文件已通过校验。

## 数据库记录缺失的恢复依据

候选方案新增独立于块登记的分段清单`export_data_segments`：每次首次收集一块，在块登记、checkpoint与进度的同一事务保存不可变分段身份、前后游标、行数、规范原始行内容摘要和当前块选择；文件I/O仍在事务外。分段清单不保存客户原文，摘要对应确定版本的规范序列化。完整收集时事务保存清单数量、总行数与有序清单摘要，标记manifestSealed；装配只接受完整且封存匹配的集合。

清单是恢复边界，不能靠猜测缺失范围或临时文件中的更多内容继续。重建只查询原任务范围与该分段的`(previousCursor,lastCursor]`，按原稳定排序、字段配置及序列化版本读源，必须得到相同行数、边界和内容摘要；否则不可安全替换。应用只读不保证外部订单永不变化。

| 检测事实 | 处理 |
| --- | --- |
| 块登记、文件、清单全部匹配 | 保留当前块选择及文件，不重新查订单或生成该数据块 |
| 文件不存在、校验不符或块登记缺失，但完整分段清单仍可信 | 标记该段待重建；根据清单重读来源并校验基线，生成新块，登记后原子切换该段选择 |
| 文件存在但没有块登记 | 不采纳孤儿文件、不计进度；有可信分段清单则重建，否则报告缺少恢复依据 |
| 清单缺失、封存摘要不符、分段重叠／空洞、配置或数据代次身份无法确定 | 无法证明原集合，不自动扩大范围／全量猜测；持久记录DATA_REPAIR_UNRECOVERABLE并失败 |
| 任务记录不存在 | 不重建任务或原命令；保留文件，按既有未知／未登记命令规则HOLD并报告，不伪造该任务FAILED |
| 数据库读失败或提交结果不明 | UNKNOWN/HOLD；不当作记录缺失，不凭本地状态继续写入或确认消息 |
| 订单区间成员、行数、内容已改变／源数据不足 | DATA_REPAIR_SOURCE_CHANGED，明确失败；保留其他匹配块，不将变化后的源混入旧结果 |
| 仅POI工作文件／候选Excel损坏，数据块全部可信 | 可信行数不扣减；关闭旧装配资源，新建Workbook重放全部块并校验，非成功仍最多99% |

清单和块登记是同库的独立恢复证据，不能承诺两者同时丢失仍可恢复。原checkpoint的连续可信前缀仍用于原收集游标，不用非连续可信块行数推进查询游标。

## 自动重试、事务和并发

1. 读取已封存清单及版本，事务外逐块完整校验，形成健康段、待重建段及不可恢复原因；发现异常即关闭当前装配资源；关闭失败按resourcesClosed=false返回UNKNOWN/HOLD，不进入下一轮装配或伪造停止证明。CHECKING只表示正在核对，保留上一次已提交计数，不宣称它已经重新核验。
2. 对账结果提交前按activity→task→原command→execution→checkpoint→repair→segment（sequence升序）→artifact→progress_outbox取锁；核验RUNNING、owner/fence/controlVersion、租约、dataGeneration、checkpointVersion、manifestVersion与repairEpoch。版本变化则丢弃旧结果重新读取，禁止过期校验回退新进度。
3. 确认可重建后递增repairEpoch、持久repairAttempt与待修段，设置REBUILDING；提交可信行数、任务／活动版本及通知意图后才开始重建。一次自动修复轮次包含整轮对账、坏段替换、重新装配及最终校验；**上限每任务3轮**，持久跨崩溃保留，不因接管、重连或换owner清零，不另加计时退避。
4. 事务外按段重读源并校验不可变内容基线，写新blockId，关闭force原子移动；短事务按repairEpoch/段选择版本CAS登记并切换，可信行数只增加一次，同时更新进度Outbox。提交不明按同repairEpoch/segment定位结果，不重复累计。已通过的其他段选择不动。
5. 全段可信后阶段ASSEMBLING，依序新建Workbook装配全部选中块；读取中再损坏则进入下一轮，不只检查首个错误后直接成功。仅候选Excel故障也消耗修复轮次，触发原因随审计传递，即使坏段列表为空仍重新装配。全部段／最终文件校验完成且成功采用事务提交后转SUCCEEDED/COMPLETE，清除重建提示，进度100%。
6. 上限耗尽时DATA_REPAIR_EXHAUSTED，路径无权限等不可重试I/O给安全分类，持久FAILED/COMPLETE；不无限重试，不输出物理路径或异常堆栈。依赖未知及失权保留原HOLD规则，不通过修复机制重置既有异常接管预算。
7. 暂停优先：修复所有登记也受控制屏障约束；PAUSING停止推进／关闭资源并走原PauseProof，PAUSED不自动修复。修复计划和已提交选择保留，暂停时提示改为“损坏文件重建已暂停”；仅有安全停止证明才能显示已暂停。

## 进度与黄色提示

任务摘要新增`executionPhase`、`repairState`、`repairEpoch`、`repairAttempt`、`repairReasonCode`；字段定义见[模型](../data-model.md#选择性重建模型)。计数由数据库`trusted_processed_count`投影为HTTP/SSE的`processedCount`。首次收集按成功登记块累计；完成校验后改为所有匹配选中段的行数之和；坏／缺／未登记段不计。每段替换提交后增加该段行数。`progressPercent=min(99,floor(processedCount*100/totalCount))`，仅成功事务后为100；空任务仍受既有不允许创建约束。

例：总10000行，对账前90%；装配对账后仅6000行可信，提交更高版本的60%，保留这些数据块，只重建其余分段。若仅Excel候选损坏而10000行数据块全可信，保持99%并重新装配，不伪造数据块进度下降。

SSE推送已提交数据库摘要，**不在每次推送核对磁盘**。后端保留原processed_high_water作历史指标，不把它当修复后的当前进度或恢复位置。前端只比较任务version，接受新版本较小的进度；不得用max合并计数，不让旧HTTP／缓存／重复消息恢复较高旧值。仅阶段／提示／进度变化不触发重排或额外列表查询。

`repairState=CHECKING`显示“正在校验文件”；进入REBUILDING后直到重建和重新装配成功，进度条后显示黄色InfoCircle，hover和键盘focus提示**“正在重建损坏文件”**，有相同可访问名称，不只用颜色表意。修复中的再次CHECKING与ASSEMBLING仍保留REBUILDING状态及黄色提示；PAUSING显示“正在暂停损坏文件重建”，PAUSED显示暂停文案；成功移除，最终失败移除运行提示并显示安全错误。刷新／重连按权威字段恢复提示，前端不以计时器自行清除。

## 存量、清理与回退

已新增V6迁移及运行校验补齐，不改V1至V5；具体文件和函数在[计划](../plan.md#选择性修复增量计划)及[函数设计](../function-design.md#选择性修复增量设计)。已有块先完整验证，证明全链和总量后才能分批幂等补齐清单并封存；不得从元数据单独制造可信基线。存量任务已丢失必要证据时明确不可恢复。尚未封存的收集中任务沿旧连续前缀规则完成后再封存，不让半份清单进入选择性装配。

旧块登记、替换历史和清单永久保留；旧保护引用不在本期释放，清理服务继续尊重所有旧记录，不能因不是当前选择就删文件。部署需停受理／消费并完成兼容迁移，运行校验补齐是后续任务执行设计，本轮不连库。已有非连续选择或修复状态后，不能回退到忽略清单、只读旧连续块的版本；关闭修复入口不清修复计划，不重置进度和预算，保留兼容版本处理或明确失败。

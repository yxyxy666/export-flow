# 任务：[功能名称]

**输入**：来自 `/specs/[###-feature-name]/` 的设计文档

**前置条件**：`plan.md`（必需）、`spec.md`（有用户故事时必需）、`research.md`、`data-model.md`、`contracts/`

**测试**：行为变更必须包含测试任务，并且测试必须先于实现；纯文档或无行为变更的任务可以不新增测试。

**验收标准追踪**：每条测试任务必须声明覆盖的 `AC-xxx` 和测试用例 ID（`TC-xxx`）；任务完成前必须先创建并运行这些测试，确认失败或记录经评审的覆盖缺口。不得存在没有测试映射的验收标准。

**组织方式**：按用户故事分组任务，以便每个故事可以独立实现和测试。

## 验收标准覆盖矩阵（必填）

| 验收标准 ID | 测试用例 ID（一个或多个） | 测试任务 ID | 实现任务 ID | 红灯证据/覆盖缺口记录 |
|---|---|---|---|---|
| AC-xxx | TC-xxx | Txxx | Txxx | [失败输出或缺口评审记录] |

> 矩阵是任务评审门禁：每个 `AC-xxx` 必须有测试任务和实现任务；测试任务必须先于对应实现任务，且保留测试失败证据或经评审的覆盖缺口。

## 格式：`[编号] [P?] [故事] 描述`

- **[P]**：可以并行执行（不同文件且无依赖）
- **[故事]**：任务所属的用户故事（例如 US1、US2、US3）
- 描述中必须包含准确的文件路径

## 路径约定

- **单项目**：仓库根目录下的 `src/`、`tests/`
- **Web 应用**：`backend/src/`、`frontend/src/`
- **移动端**：`api/src/`、`ios/src/` 或 `android/src/`

## 依赖关系与执行顺序

### 阶段依赖

- **准备（阶段 1）**：无依赖，可立即开始
- **基础能力（阶段 2）**：依赖准备阶段完成，并阻塞所有用户故事
- **用户故事（阶段 3 及以后）**：都依赖基础能力阶段完成；之后可并行或按 P1 → P2 → P3 顺序执行
- **收尾阶段**：依赖所有目标用户故事完成

### 用户故事依赖

- **用户故事 1（P1）**：基础能力阶段完成后开始，不依赖其他故事
- **用户故事 2（P2）**：基础能力阶段完成后开始，可与 US1 集成，但必须独立测试
- **用户故事 3（P3）**：基础能力阶段完成后开始，可与 US1/US2 集成，但必须独立测试

### 单个用户故事内部顺序

- 行为变更必须先编写并确认测试失败；纯文档变更可以省略测试
- 先模型，后服务
- 先服务，后接口
- 先核心实现，后集成
- 当前故事完成后再进入下一个优先级

### 可并行机会

- 标记 `[P]` 的准备任务可以并行
- 阶段 2 中标记 `[P]` 的基础任务可以并行
- 阶段 2 完成后，所有用户故事可以并行（取决于团队容量）
- 单个故事的测试任务可以并行
- 单个故事中的模型任务可以并行
- 不同成员可以并行处理不同用户故事

## 并行示例：用户故事 1

```bash
# 同时启动用户故事 1 的所有测试（如果属于行为变更）：

Task: "在 tests/integration/test_[name].py 编写[用户旅程]集成测试"

# 同时启动用户故事 1 的所有模型任务：
Task: "在 src/models/[entity1].py 创建[实体 1]模型"
Task: "在 src/models/[entity2].py 创建[实体 2]模型"
```

## 实施策略

### 优先交付 MVP（只实现用户故事 1）

1. 完成阶段 1：准备
2. 完成阶段 2：基础能力（关键：阻塞所有故事）
3. 完成阶段 3：用户故事 1
4. **暂停并验证**：独立测试用户故事 1
5. 就绪后部署或演示

### 增量交付

1. 完成准备和基础能力，基础设施就绪
2. 增加用户故事 1，独立测试后部署/演示（MVP）
3. 增加用户故事 2，独立测试后部署/演示
4. 增加用户故事 3，独立测试后部署/演示
5. 每个故事都应增加价值且不破坏已有功能

### 团队并行策略

1. 团队共同完成准备和基础能力
2. 基础能力完成后：成员 A 负责用户故事 1，成员 B 负责用户故事 2，成员 C 负责用户故事 3
3. 各故事独立完成并集成

## 注意事项

- `[P]` 表示不同文件且无依赖
- `[故事]` 标签用于追踪任务对应的用户故事
- 每个用户故事都应能独立完成和测试
- 实现前确认测试失败
- 只有功能达到项目提交门禁后才能提交，不提交未完成的功能
- 可在任意检查点暂停并独立验证故事
- 避免模糊任务、同文件冲突以及破坏独立性的跨故事依赖

# ADR-0010 本地基础设施独立初始化

- 状态：已接受
- 日期：2026-10-20
- 批准依据：负责人要求参考示例项目迁移基础设施生成逻辑，并进一步明确：别人拿到当前项目、没有任何基础设施时，先直接执行make命令生成基础设施，再执行make dev启动应用；本次无需规格。
- 取代范围：[ADR-0009](0009-engineering-runtime-and-progress-notification.md)中“不新增Compose”、仅依赖示例容器的限制，以及本轮初稿的“跨项目自动复用容器、make dev创建基础设施”方案。

## 决策

标准流程为`make infra`、`make dev`，两个命令职责独立。参考示例的Compose服务、MySQL初始化机制及RabbitMQ配置方式，迁入MySQL8.4、Redis7.4、RabbitMQ3.13。应用继续在宿主机运行；不增加应用容器化、远程部署或CI。

[基础设施入口](../../scripts/start-infrastructure.ps1)首次自动生成随机凭据和应用连接配置，用[本项目Compose](../../docker-compose.yml)创建固定项目名export-flow的完整服务与持久卷，等待本项目三个服务健康。只查询该Compose项目，不扫描端口以发现其他容器，不复用示例或其他项目的基础设施。重复执行保留本项目容器、凭据及数据；端口冲突明确失败。

MySQL初始化脚本只挂载到本项目空数据卷首次启动的entrypoint，创建export_flow应用库、exportflow来源库、与示例V1/V6契约兼容的空orders表，以及独立运行／迁移账号。运行账号有应用库DML和来源SELECT权限；迁移账号有应用库DDL及来源SELECT/REFERENCES权限。业务任务表、视图和后续升级仍由应用Flyway管理，不复制示例应用的任务表或Flyway历史。

RabbitMQ初始化/export-flow vhost和本地账号；固定hostname保证持久卷节点身份。端口仅绑定回环接口。四个独立随机密码保存在忽略的.env.infrastructure.local，应用.env.local自动使用对应值。已有应用配置的基础设施连接字段先完整备份再同步，应用端口、文件根等其他设置保留；字段已一致时不重写、不重复备份。该规则避免旧环境密码使新容器启动后应用认证失败。备份同样被Git忽略。

## 业务数据边界

全新环境创建空订单来源表是启动必需结构，不恢复已删除的订单造数工具、不生成演示或性能订单。不读取、复制、更新或删除其他环境的订单，也不修改其账号、容器、卷及全局策略。现有订单只读适配契约保持不变。历史110000条示例订单是旧环境事实，不成为新环境初始化的前置条件。

新基础设施可供应用从空库启动；订单列表初始为空。既有依赖固定来源行数的历史业务测试，不因空库初始化而宣称通过，测试来源要求另行按既有任务范围准备。

## 验证及回退

[编排回归](../../tests/scripts/start-infrastructure.test.ps1)覆盖零配置生成、配置一致性、重复执行保留、项目隔离和失败路径。真实空卷初始化、权限与应用启动证据见[验证记录](../validation/local-infrastructure-bootstrap.md)。标签沿用示例，正式验收继续记录实际版本和digest。

停止应用保留基础设施；失败时不自动down、删除卷、清库或删除导出文件。旧环境可保留其应用配置并单独启动应用，不由新入口接管。项目通用规格审批原则不因本次免规格而改变。

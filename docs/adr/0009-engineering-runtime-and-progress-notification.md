## 本地工程与测试

采用Java 21、Spring Boot 3.5、Spring MVC、Maven 3.9 Wrapper；测试采用JUnit Jupiter、AssertJ、Spring Boot Test、MockMvc和Testcontainers。关键边界使用真实MySQL 8.4、RabbitMQ 3.13和Redis 7.4隔离环境，不改用H2。Redis暂不升级8，未来变更单独评审。

MySQL使用READ COMMITTED；候选扫描与授权分开。并发领取使用短事务、固定锁序及FOR UPDATE SKIP LOCKED，不先锁Outbox再回锁task。隔离、锁定SQL的运行正确性须在测试阶段证明，选型确认不等于已经运行通过。

本地应用运行在宿主机，后端只绑定127.0.0.1:8080，Vite只绑定127.0.0.1:5173并将/api代理到后端。复用现有中间件；项目使用独立schema、vhost和键前缀。文件根由外部配置，默认位于LOCALAPPDATA下的ExportFlow/data，不放进仓库或进程临时目录。本期不新增Compose，不部署远程环境。

本期只使用本地自动化门禁，不新增托管CI工作流。交付物为前端dist目录与后端可执行jar，构建报告与来源摘要保存在本地artifacts；版本控制只提交小型验证证据。后续远程发布、应用容器化和多主机文件存储已明确延期，不作为当前缺失选型。

## 命令保留与异常消息

本地使用durable direct exchange、durable classic queue、persistent消息、mandatory和相关发布确认。队列无TTL、expiry、自动删除或drop-head；本期不设置队列长度上限，以监测和停止新受理处理容量风险。不得给原命令配置自动死信或重交付次数上限，使仍需执行的命令被静默删除。

畸形消息、未知协议版本或不存在任务的处理选择为保留原未确认消息，停止受影响消费槽，受控关闭通道并告警；不ACK、不自动转死信、不立即循环重入队。修复来源或确认受控处置后人工重新启用消费；本期不提供消息修复后台。单消费者场景可能因此停止整个导出消费，这是保留消息的明确取舍。重启仍遇到同一消息时再次停止，不能自动忽略。此决定沿用[ADR-0006](0006-broker-owned-pending-delivery.md)的确认边界。

## 后续SSE与Redis方向

完整任务页面后续采用Spring MVC SseEmitter。单一环境内全部任务为可见范围，无虚构用户隔离；默认排序保持创建时间、任务ID倒序，活跃优先及依赖它的进度排序方案撤出。

连接只在页面可见且快照显示活跃任务时建立，同页最多一条。隐藏立即关闭；进入、恢复可见、恢复联网、手动刷新及本浏览器新任务通知执行一次MySQL快照，再决定连接。正常stream-idle关闭后不自动重连；其他设备在空闲关闭后创建任务不会自动唤醒本页，接受此限制，不注册任何固定或低频前端轮询。

stream-idle宽限1秒，以持久活动版本与MySQL事务裁决创建竞态；心跳注释15秒。异常重连采用1至30秒指数退避全抖动，每次重连先快照；事件ID表达活动/任务版本，不承诺历史回放，Last-Event-ID不能跳过快照。具体端点、DTO和前后端函数留后续功能规格，协议原则不再待选。

Redis只缓存版本化最新进度，TTL10分钟，应用最多保留10000个活跃任务缓存键；超过上限跳过写缓存并回源MySQL，不调整共享Redis的全局maxmemory或淘汰策略。Lua版本比较拒绝旧进度，终态/下载/空闲裁决查MySQL。缓存故障不影响已提交业务状态。

可靠跨实例通知选择独立的进度Outbox：可观察变化与待通知版本同事务提交，允许按taskId合并到最新版本；独立dispatcher向durable fanout exchange发布最小taskId/version。每个配置稳定实例ID的SSE API实例使用自己的durable queue、手动确认，先读取不低于通知版本的缓存或MySQL权威摘要并向本地连接发送，再确认。进度Outbox和任务命令Outbox不同，不能用于重投任务。

通知未确认、依赖不可读或广播失败时保留通知并有界退避。实例重启用原稳定队列，客户端重连总是快照；连接发送失败关闭连接，客户端快照恢复。任务进入终态且相应终态通知发布已确认后才清理通知Outbox记录，已入队通知由各实例消费确认；永久业务记录不受影响。广播拓扑及数据库结构由后续规格细化并测试，本期不创建它们。

## 质量与验证取舍

后端采用Spotless、Checkstyle、SpotBugs和JaCoCo；前端使用现有类型检查、Vitest及生产构建。实现完成后的门禁要求格式/检查通过、SpotBugs高置信高优先级问题为零，覆盖率生成报告但不设置未经基线验证的百分比阈值。无浏览器E2E门禁；目标为Windows上当前稳定Chrome和Edge，1280×720及键盘/焦点手工验证。IAB是开发检查辅助工具，其未知精确版本不再作为目标浏览器认证依据。

性能采用本机记录的参考配置、独立512MB JVM、固定种子、独立服务和串行负载，详见[决策记录](../../specs/002-order-management/decision-record.md)。环境事实、实际测试证据和验收缺口继续据实记录，不能通过决策批准将未执行验证标为通过。

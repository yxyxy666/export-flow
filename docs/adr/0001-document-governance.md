# ADR-0001 文档治理与 SDD/TDD 门禁

- 状态：已接受
- 日期：2026-09-12

## 背景

模型需要稳定入口和局部规则；中高风险变更需要先明确契约再实现。

## 决策

采用 `AGENTS.md` 作为最高项目治理源和唯一文档索引；将 GitHub Spec Kit 的
`.specify/memory/constitution.md` 定义为开发阶段治理源，并使用 `spec.md`、`plan.md`、
`tasks.md` 标准产物；按规则域拆分项目细则；中高风险变更执行规格评审 →
TDD 测试先行 → 实现 → 项目工具链验证门禁；架构权衡记录在 ADR。

## 后果

增加文档维护成本，但降低模型误读和隐式约定风险。AGENTS.md 与
constitution 需要同步维护；规格流程只覆盖开发阶段的文档工作，不替代项目的
测试、构建、打包、容器和发布工具链。

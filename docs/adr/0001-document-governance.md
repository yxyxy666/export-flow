# ADR-0001 文档治理与 SDD/TDD 门禁

- 状态：已接受
- 日期：2026-09-12
- 补充日期：2026-10-04；依据项目负责人明确要求，补充规格函数草稿、测试进度和测试先行阶段独立审批。

## 背景

模型需要稳定入口和局部规则；中高风险变更需要先明确契约再实现。

## 决策

采用 `AGENTS.md` 作为最高项目治理源和唯一文档索引；将 GitHub Spec Kit 的
`.specify/memory/constitution.md` 定义为开发阶段治理源，并使用 `spec.md`、`plan.md`、
`tasks.md` 标准产物；按规则域拆分项目细则；中高风险变更执行规格评审 →
TDD 测试先行 → 测试阶段门禁通过 → 项目负责人审批测试先行阶段 → 实现 → 项目工具链验证门禁；架构权衡记录在 ADR。

每次规格准备必须设计目录、逐文件内容及前后端和必要通用函数的签名、中文职责注释、
简短流程与调用关系，设计草稿由 `plan.md` 承载或链接附属清单；`tasks.md` 从规格阶段起
维护测试进度、证据和两次独立审批记录。细则见[规格准备规则](../rules/specification.md) 与
[测试规则](../rules/testing.md)。规格审批不授权生产实现，测试自动通过不替代测试阶段的人类审批。

## 后果

增加文档维护成本，但降低模型误读和隐式约定风险。AGENTS.md 与
constitution 需要同步维护；规格流程只覆盖开发阶段的文档工作，不替代项目的
测试、构建、打包、容器和发布工具链。

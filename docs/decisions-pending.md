- 项目已决定不使用任何固定或低频轮询。SSE 正常关闭后，其他设备或服务端入口新建的任务无法自动唤醒当前页面。**建议**：本期接受该限制，只在进入/恢复页面、恢复联网和手动刷新时执行一次快照查询；若未来要求跨设备即时发现，则必须重新评审永久通知通道或 Web Push。

## 后端实现选择

- [`AC-028`](product/acceptance-criteria.md#ac-028) 是当前已确认的默认排序；[`AC-036`](product/acceptance-criteria.md#ac-036) 是待审批的活跃优先方案，二者不能同时实施。候选 [`AC-037`](product/acceptance-criteria.md#ac-037) 使用了活跃优先方案的状态优先级，不能单独获批。**待决策**：是否将默认排序改为活跃优先；若批准，明确由候选标准取代现行标准，保留原编号和定义并同步 PRD、前端规则和测试映射。评审前保持创建时间倒序。

- MyBatis 动态 SQL 与 Flyway Schema 演进已由 [`ADR-0005`](adr/0005-backend-stack-and-progress-cache.md) 确认为选型；具体依赖版本、MySQL 事务隔离级别和 Outbox 并发领取 SQL 尚未确定，须在真实 MySQL 8.4 LTS 上验证。
- 当前开发阶段复用的 Redis 实际为 `redis:7.4-alpine`，见[环境记录](rules/container.md#当前开发环境已确认)。Redis 8 候选环境与现有版本的兼容性、后续是否升级及镜像锁定尚未确定，容器专项再统一；可重建进度缓存的有效期、容量和资源参数仍待确定。缓存故障应从 MySQL 回源，跨实例通知机制另行评审。
- RabbitMQ 的镜像版本、持久化、exchange/queue/routing key、发布确认与正确路由确认、消费者并发、预取量、重投、死信和 Worker 执行中断后的恢复尚未确定。**建议**：按容量验证后配置，并在真实 broker 上验证发布前后及消费确认前后的崩溃窗口。手动消费确认边界见 [`ADR-0006`](adr/0006-broker-owned-pending-delivery.md)。
- Outbox 补投的具体实现参数尚未确定：常规投递扫描周期、批次、并发、发布超时、租约期限、退避上下限与抖动参数、并发领取及三方裁决 SQL、目标队列类型与容量、可靠路由检查的具体配置、告警阈值和已发送/已关闭记录保留周期。后续方案必须遵守已接受的 [`ADR-0007`](adr/0007-outbox-dispatch-retry.md)，不能以参数选择重新改写补投原则、总投递窗口或超时失败规则。
- Worker 执行锁必须带 owner、到期时间及心跳续租，续租失败的执行者不能继续推进任务；这些需求前提已提出。MySQL 授权、失权停止与到期接管的完整协议、领取与执行的独立超时、旧执行者隔离、尝试上限，以及队列与消费者健康监测告警仍待架构及规格评审，见下文及 [`ADR-0008`](adr/0008-worker-execution-lease-and-recovery.md)。Worker 执行失败与恢复耗尽是否置为 `FAILED` 须明确审批，不能与命令投递耗尽混为一谈，也不因 Outbox 补投原则已确认而自动获批。
- Worker 已收到消息但连接持续存活、却长期卡在 MySQL 认领之前时，RabbitMQ 只知道投递未确认，不知道任务是否开工。应用侧认领监测器的交付时间记录、MySQL 状态核对、认领阈值、通道隔离、认领提交与关闭通道竞态及监测器自身故障恢复尚未确定。**建议**：收到后立即条件认领；认领超时且 MySQL 仍为 `PENDING` 时告警，受控关闭对应通道，使 RabbitMQ 重交付未确认消息；关闭通道前后须防止原 Worker 在认领成功后与新 Worker 重复生成。RabbitMQ 的消费确认超时另按最长文件生成时间设定和验证，不能拿短认领阈值直接替代。两种超时都不能仅凭排队时长把任务判为失败，见 [`ADR-0006`](adr/0006-broker-owned-pending-delivery.md)。
- Redis 最新进度缓存、MySQL 事实源与 SSE 广播的职责见 [`ADR-0005`](adr/0005-backend-stack-and-progress-cache.md)。在线活跃进度通知优先读取缓存，初次/断线快照及终态裁决使用 MySQL；缓存版本比较、有效期、容量、重建规则，以及跨实例 SSE 通知和在线漏通知补偿仍待批准。普通订单/任务列表不默认缓存。
- Spring SSE 技术路径尚未确定。**建议**：保持现有同步 Spring MVC 栈并使用 `SseEmitter`，当前规模没有引入 WebFlux 双栈的收益。
- 相同 `Idempotency-Key` 携带不同载荷时的 HTTP 状态和错误码尚未确定；规范化请求摘要怎样处理 `SELECTED` 订单 ID、`FILTERED` 条件和有序字段也待审批。**建议**：冲突返回 `409 Conflict` 和稳定错误码 `IDEMPOTENCY_KEY_REUSED`，不得返回原任务掩盖调用错误；字段顺序保留业务含义，其他等价输入的规范化规则在契约中明确，并用并发同键测试验证。
- SIGTERM 时正在生成的任务如何结束尚未确定。候选原则见 [`ADR-0008`](adr/0008-worker-execution-lease-and-recovery.md)：停止新领取，在有界宽限内完成；超时后保存可信断点、停止执行和续租并受控关闭通道，不能先释放执行锁再让旧执行器继续写入，也不能删除可恢复数据。部署停机不等于用户暂停，已有用户暂停意图不能因重启丢失。待明确审批。

## Worker 执行架构候选

[`ADR-0008 Worker 执行权、用户暂停、断点恢复与竞态隔离`](adr/0008-worker-execution-lease-and-recovery.md) 已形成待评审提案。项目负责人已补充执行锁的有效期与续租前提，并要求将恢复授权、持久化续写能力和重复执行安全分别判断；整份架构、产品状态及规格仍待评审，不是实施授权。

- **领取与执行锁**：建议 RabbitMQ 管消息交付，MySQL 短事务认领并原子建立带唯一尝试 owner、数据库到期时间和单调隔离代次的执行租约，事务提交后释放行锁；不另设永久领取标志。认领监测超时、执行租约有效期、心跳间隔、尝试最大期限和 broker 消费确认超时分别验证，dispatcher 投递租约也独立。Redis 不参与执行权。
- **续租失败与重新领取**：建议心跳只给当前有效 owner 条件续租，提交成功才认可新到期时间。续租被拒绝或结果不明时立即停止新批次和业务提交、核对并协调关闭通道；重新交付的 Worker 仅在权威租约过期或安全废止后争取新执行权，不以本地失败立即抢锁，旧心跳不能复活旧身份。
- **用户暂停与恢复**：建议持久化用户意图和控制版本，安全保留已提交断点（若有）并停止后才登记暂停生效；暂停不能自动接管，也不承诺一定产生断点。暂停生效后确认本轮消息，显式恢复时在原任务事务中创建独立恢复命令 Outbox，不重置原 `SENT` 创建命令。此消息确认扩展、恢复投递口径和产品状态须明确审批并同步已有 ADR。
- **恢复授权与续写能力**：用户暂停决定须等待显式恢复，异常决定是否按预算自动接管；两种入口取得授权与执行权后均按持久事实判定。暂停时首批尚未登记会没有断点，被 kill 之前已登记的可信断点仍可续写。建议先核对结果与连续断点；暂时不可访问不等于已经损坏。
- **持久化续写方案**：前提是任务能稳定切分批次，每批完成后先持久化可复用数据，再同事务登记数据引用、游标、进度和新版本。条件更新检查 owner、隔离代次、数据代次及预期前序版本，防止旧 Worker 和同一尝试的乱序覆盖。候选方案使用不可变临时数据块与 MySQL 连续清单，最终 SXSSF Excel 从这些文件装配；装配中断可重新装配，不假定半成品 XLSX 任意追加。仅有条数或缓存不足以续写，引用文件须跨重启保留。具体格式、批次大小、版本字段和游标留待规格。
- **安全重做前提**：无可信断点时从头重建、未登记末批重做及 Excel 重新装配，均须证明无业务副作用或已有持久幂等与结果对账能力。候选导出以只读源数据、固定配置、尝试隔离文件和唯一结果引用实现安全重做；请求创建幂等不等于执行幂等。无法证明重复安全时不得自动重跑，对账或失败的用户结果仍待审批。
- **竞态与文件**：建议尝试路径隔离，旧执行者不能登记新断点或覆盖新结果；可信就绪文件经核对后可采用。暂停断点的数据块必须保留，不能因租约过期或无活跃 Worker 清理。
- **恢复终止**：建议不可恢复错误或异常恢复预算耗尽时提交执行失败，随后确认消费；用户暂停不消耗异常恢复预算。该原则、失败原因和完整重建后的进度展示仍需审批并同步产品需求及验收基线，不能直接沿用投递超时规则。
- **故障隔离与存储边界**：建议消费监督器独立于文件生成，执行槽可受控隔离；本期多 Worker 接管限定在同主机共同可访问的本地文件命名空间，不自动批准跨主机共享存储或对象存储。此范围待确认。
- **独立未决架构**：消费端非法消息、未知版本和任务不存在的隔离与恢复，以及可靠 SSE 通知仍待评审；不因 Worker 提案而获得批准。broker 重交付限制不得静默丢弃未终态命令，限制与可靠隔离恢复须一起评审。

暂停状态和接口、控制版本、恢复消息和断点版本字段、数据块格式与大小、稳定游标、认领超时、租约有效期与心跳间隔、尝试期限、恢复上限、退避、预取、SQL、目录布局和清理参数属于后续规格或运行方案，不在本轮架构讨论中固定。重复执行安全须有验证证据，不安全时的对账或失败结果仍待决策。架构获批后再同步相关上游文档；进入实施准备时按项目门禁生成并审批标准规格。

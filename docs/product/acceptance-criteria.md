## 订单查询与选择

<a id="ac-001"></a>
### AC-001 初始查询

给定用户进入订单管理页面，当页面加载完成时，那么页面展示筛选区、操作区、订单表格和分页区，并立即按无筛选条件查询第一页，分页默认每页 20 条。

<a id="ac-002"></a>
### AC-002 组合筛选

给定用户填写一个或多个筛选条件，当点击“查询”时，那么系统按照全部已填写条件的“并且”关系查询，并从第一页展示结果。

<a id="ac-003"></a>
### AC-003 重置

给定用户已经设置筛选条件或勾选订单，当点击“重置”时，那么系统清空筛选条件和已选订单，恢复第一页及每页 20 条，并立即按无筛选条件查询第一页。

<a id="ac-004"></a>
### AC-004 订单分页

给定查询结果超过一页，当用户切换页码或将每页数量设置为 20、50、100 时，那么系统展示对应页面的数据、当前页、每页数量和总条数；修改每页数量后返回第一页。

<a id="ac-005"></a>
### AC-005 范围校验

给定开始时间晚于结束时间，或最小金额大于最大金额，当用户发起查询时，那么系统阻止查询并给出可理解的校验提示。

<a id="ac-020"></a>
### AC-020 跨页选择生命周期

给定用户已经勾选订单，当切换分页时，那么系统保留已勾选订单；当用户修改筛选条件并重新查询时，那么系统清空此前勾选并展示新查询结果。

<a id="ac-021"></a>
### AC-021 订单号精确匹配

给定用户输入订单号，当执行查询时，那么系统仅返回订单号完全相等的订单。

<a id="ac-022"></a>
### AC-022 时间边界与时区

给定用户按 `Asia/Hong_Kong` 选择精确到秒的下单时间范围，当执行查询时，那么系统将开始和结束时间转换为 UTC，并包含恰好等于两个边界的订单。

<a id="ac-023"></a>
### AC-023 金额边界

给定用户输入最小金额和/或最大金额，当执行查询时，那么系统包含金额恰好等于已填写边界的订单。

<a id="ac-024"></a>
### AC-024 订单稳定排序

给定多条订单具有不同下单时间或相同下单时间，当展示查询结果时，那么系统按下单时间倒序、再按订单唯一 ID 倒序稳定排列。

<a id="ac-033"></a>
### AC-033 订单选择工具

给定订单列表有多页，当用户在不同页面勾选订单时，那么已选数量和订单集合跨页保留；点击“全选当前页”“反选当前页”或“清空已选”时，只按按钮语义更新选择集合。

<a id="ac-034"></a>
### AC-034 订单排序切换

给定订单表格已展示，当用户切换下单时间排序时，那么结果按升序或降序稳定排列，相同时间按订单 ID 同方向排序，并回到第一页。

<a id="ac-035"></a>
### AC-035 订单关键字搜索

给定用户输入关键字并查询，当关键字匹配订单号、客户姓名或手机号任一字段时展示该订单；匹配不区分英文大小写，并与其他筛选条件使用“并且”关系。

## 创建导出任务

<a id="ac-006"></a>
### AC-006 导出已选订单

给定用户至少勾选一笔订单，当点击“导出已选”、选择导出字段并确认时，那么系统基于已选订单和所选字段创建一个异步导出任务。

<a id="ac-007"></a>
### AC-007 无选择时禁用

给定用户没有勾选任何订单，那么“导出已选”不可用，并显示不可用原因。

<a id="ac-008"></a>
### AC-008 导出筛选结果

给定当前筛选结果不为空，当点击“导出筛选结果”、选择导出字段并确认时，那么系统基于符合当前筛选条件的全部订单和所选字段创建异步导出任务，导出范围不受当前页限制。

<a id="ac-009"></a>
### AC-009 空结果时禁用

给定当前筛选结果为空，那么“导出筛选结果”不可用，并显示不可用原因。

<a id="ac-010"></a>
### AC-010 创建幂等

给定系统收到多个携带同一 `Idempotency-Key` 的创建导出任务请求，那么这些请求只对应一个导出任务，不产生重复文件。

<a id="ac-011"></a>
### AC-011 大任务异步接受

给定导出范围包含十万条以上且不超过 200,000 条订单，当用户成功提交导出时，那么系统接受任务并允许用户通过导出任务列表查看后续状态，而不是等待文件在订单列表请求中直接返回。

<a id="ac-019"></a>
### AC-019 导出上限

给定导出范围超过 200,000 条订单，当用户尝试创建任务时，那么系统不创建任务，并提示当前数据量、单次上限以及缩小筛选范围或减少勾选数量。

<a id="ac-025"></a>
### AC-025 创建成功跳转

**状态：2026-10-11 按负责人要求撤出，替代行为见 [`AC-072`](#ac-072)；原意保留，编号不复用。**

给定用户成功创建导出任务，当接口返回新任务时，那么系统清空已选订单并自动进入导出任务页面。

<a id="ac-030"></a>
### AC-030 创建失败保留状态

给定创建导出任务请求失败，当系统展示错误时，那么用户仍停留在订单管理页面，筛选条件、导出字段和已选订单保持不变。

<a id="ac-050"></a>
### AC-050 创建成功以事务提交为前提

给定首次创建导出任务，当后端向前端返回创建成功和任务 ID 时，那么 MySQL 中必须已经提交可按该 ID 查询的任务及与其同事务创建的命令 Outbox；事务明确回滚时不得返回创建成功。响应到达时 Outbox 可能已被后台标记为 `SENT`；创建成功不要求 RabbitMQ 已收到消息，也不要求文件已生成。

<a id="ac-051"></a>
### AC-051 创建结果不明时找回同一任务

给定创建请求超时、连接中断或事务提交结果无法确认，当用户按原请求内容和原 `Idempotency-Key` 重试时，那么前端在得到明确结果前不宣称创建成功或失败，并保留筛选条件、导出字段和已选订单；后端若核对到同键同请求已提交，返回同一任务的当前摘要，不创建第二个任务或文件。

## 补投自动失败与可靠性

<a id="ac-052"></a>
### AC-052 未确认投递的总窗口自动失败

给定任务及原命令 Outbox 已提交，当数据库时间达到创建事务持久化的受理时间加 10 分钟，且任务仍为 `PENDING`、原命令未 `SENT` 且未关闭时，后台自动扫描须在同一事务将任务置为 `FAILED`、记录结束时间与 `TASK_DISPATCH_TIMEOUT`、关闭原命令并撤销领取权，无需人工批准。扫描启动周期为 5 秒，启动恢复时也检查；不受退避、有效租约或 MQ 是否可用影响。数据库或后台不可用时允许延迟提交，但恢复后须处理到期记录，不重置截止时间。用户看到“任务投递超时，未开始执行。请重试或重新创建任务。”；原记录保留，失败重试沿用 [`AC-016`](#ac-016) 的新任务语义，新建使用新提交幂等标识，重放旧标识只返回原失败任务。

<a id="ac-053"></a>
### AC-053 超时、认领与发布确认的并发裁决

给定超时失败与 Worker 认领或 dispatcher 标记发送并发，当数据库串行化裁决时，未发送且仍待执行的任务到期后不得再获得新的认领或发送成功标记；期限内已成功认领、已提交 `SENT` 或已终态的任务不得被该投递超时规则改为失败。失败与 Outbox 关闭提交后，迟到确认不能重开记录，旧消息只能在核对已提交终态后确认消费，不生成文件或改变原失败结果；数据库不可读时不提前确认。

<a id="ac-054"></a>
### AC-054 单条坏记录不阻断正常补投

给定同批 Outbox 包含载荷序列化失败、不支持的版本或不可路由的单条记录，当该记录处理失败时，其诊断与调度被保留，不删除或永久跳过，其他可处理记录继续投递且已成功标记不回滚；坏记录满足总窗口条件后自动失败。共享数据库或 MQ 连接故障须与单条错误区分，恢复后可继续扫描。

<a id="ac-055"></a>
### AC-055 崩溃接管保持尝试历史和退避

给定投递领取事务已提交，当 dispatcher 在发布或失败回写前崩溃，或记录被过期接管时，那么已持久化的尝试历史和截止时间不得重置，接管须同时满足领取权到期与持久退避到期，失败回写缺失不能绕过退避；到总截止时间后由自动失败路径处理，不因下一次重试时间更晚而无限等待。

<a id="ac-056"></a>
### AC-056 已确认命令的队列保留

给定命令已可靠存储在获批目标任务队列并标记 `SENT`，当 broker 正常重启或队列达到配置容量上限时，那么未消费命令不得因消息 TTL、自动删除或淘汰旧消息而静默丢失，容量不足须拒绝新发布且不能错误标记 `SENT`；队列有效策略不符合保留要求时须阻止不合规发布成功标记并告警。灾难性损坏及人为误删不作为本条的正常恢复保证，不据排队时长自动复制或失败任务。

## 查看与处理导出任务

<a id="ac-012"></a>
### AC-012 持续显示任务进度

给定任务处于等待中或生成中，当用户查看导出任务列表时，那么系统显示任务状态以及已处理条数、总条数和百分比，并持续更新进度。

<a id="ac-013"></a>
### AC-013 下载成功文件

给定任务已完成，当用户点击“下载”时，那么系统向用户提供对应的 Excel 文件。

<a id="ac-014"></a>
### AC-014 非成功任务禁止下载

给定任务处于等待中、生成中或失败状态，那么下载操作不可用，并显示不可用原因。

<a id="ac-015"></a>
### AC-015 成功任务元数据

给定任务已完成，当用户查看任务时，那么系统显示文件名、结束时间和文件大小。

<a id="ac-026"></a>
### AC-026 任务状态筛选

给定用户选择全部、等待中、生成中、已完成或失败状态，当执行任务筛选时，那么系统从第一页展示对应状态的任务；“全部”不附加状态条件。

<a id="ac-027"></a>
### AC-027 任务分页

给定导出任务超过一页，当用户切换页码或将每页数量设置为 20、50、100 时，那么系统展示对应页面、当前页、每页数量和总条数；默认每页 20 条，修改每页数量后返回第一页。

<a id="ac-028"></a>
### AC-028 任务稳定排序

给定导出任务列表正在展示，当列表首次加载或进度数据刷新时，那么任务按创建时间倒序、再按任务唯一 ID 倒序稳定排列。

<a id="ac-031"></a>
### AC-031 刷新保持当前页

给定用户正在查看非第一页任务，当普通进度数据刷新完成时，那么系统仍展示刷新后的当前页。

<a id="ac-036"></a>
### AC-036 活跃任务优先

**状态：2026-10-07已撤出；保留原意，编号不复用。** 决定沿用 [`AC-028`](#ac-028) 默认排序，本条不进入实施范围。

给定任务列表包含不同状态，当使用默认排序时，那么等待中和生成中的任务排在终态任务之前；生成中按进度降序排列；同组同进度按创建时间倒序、任务 ID 倒序稳定排列。

<a id="ac-037"></a>
### AC-037 进度排序

**状态：2026-10-07随 [`AC-036`](#ac-036) 撤出；保留原意，编号不复用。** 当前不提供本条所描述的进度排序。

给定用户切换进度排序，当选择升序或降序时，那么任务按百分比排序，并以默认状态优先级、创建时间和任务 ID 作为稳定次序；操作后回到第一页。

<a id="ac-038"></a>
### AC-038 任务关键字搜索

给定用户输入关键字并查询，当关键字匹配任务编号或文件名时展示该任务，并与状态筛选使用“并且”关系。

<a id="ac-016"></a>
### AC-016 失败任务重试

给定任务失败，当用户执行重试时，那么系统按原任务的导出范围和字段配置创建一个具有新任务编号的任务，并保留原失败任务记录供后续查看；初始化后的订单数据只读，因此原筛选范围不会因数据变化而漂移。

<a id="ac-017"></a>
### AC-017 非失败任务禁止重试

给定任务处于等待中、生成中或已完成状态，那么重试操作不可用，并显示不可用原因。

<a id="ac-018"></a>
### AC-018 永久保留

给定任意时间创建的导出任务，当用户查看任务记录和已完成任务的文件时，那么记录与文件仍然保留，已完成任务仍可下载。

<a id="ac-032"></a>
### AC-032 重试后返回第一页

给定用户成功重试失败任务，当新任务创建完成时，那么系统返回导出任务列表第一页，并保留原失败任务记录。

<a id="ac-049"></a>
### AC-049 已发送任务的队列交付与认领

给定命令 Outbox 已确认发送而导出任务仍为 `PENDING`，当消息在队列等待或已交付但尚未被 Worker 在 MySQL 中认领时，系统不得仅因等待超过固定时长就自动补投同一任务或将其标记为 `FAILED`；Worker 断连且未确认消费的消息可重新交付，收到消息的 Worker 只有成功提交 `PENDING -> RUNNING` 才能生成文件，重复消息不得生成第二份文件。Worker 仅收到消息时不得提前确认消费，业务终态已提交或权威状态证明无需处理后才能确认消费。

## 按需 SSE 生命周期

<a id="ac-039"></a>
### AC-039 活跃时更新、终态后停止

给定任务页可见且存在 `PENDING` 或 `RUNNING` 任务，当进度通道启动时，那么进度持续更新且不回退；全部任务进入终态后通道关闭。mock 阶段验证相同生命周期，但不得声称真实 SSE 已完成。

<a id="ac-040"></a>
### AC-040 单例通道唤醒

给定任务页可见且当前没有活跃进度通道，当创建或重试产生新任务、页面重新可见或执行刷新发现活跃任务时，那么系统建立一个通道；同一时刻不得存在重复通道。页面隐藏期间不得仅因新任务产生而建立通道。

<a id="ac-042"></a>
### AC-042 服务端显式空闲标记

给定真实 SSE 通道中的任务均已进入终态，当后端经过空闲宽限期并再次确认没有活跃任务且活动版本未变化时，那么后端发送 `stream-idle` 标记并结束响应；前端收到属于当前通道且没有更新活动的标记后主动关闭 `EventSource`，不得因该次正常空闲关闭自动重连。

<a id="ac-043"></a>
### AC-043 创建与空闲判定竞态

给定创建或重试新任务与后端空闲判定并发发生，当两者无法证明严格先后或创建/重试提交使活动版本变化时，那么新任务优先，后端取消本次 `stream-idle`，经过宽限期后重新判断；不得用前后端墙上时间或相等时间戳决定顺序。

<a id="ac-044"></a>
### AC-044 空闲关闭后重新开启

给定 SSE 已因 `stream-idle` 正常关闭，当本客户端创建或重试成功、任务页首次进入或恢复可见、浏览器恢复联网、手动刷新，或同浏览器其他标签页通知新任务时，那么前端执行一次快照查询并在存在活跃任务时重新建立唯一 SSE 通道；异常断线按受控退避重连，不视为正常空闲关闭。系统不得注册固定或低频轮询。

<a id="ac-079"></a>
### AC-079 排除范围持久化与兼容

给定FILTERED请求带排除ID，服务端严格校验字符串ID、去重和长度边界，按照相同筛选及排除规则计算数量、持久化范围并分批生成文件，排除订单不得写入Excel。范围在进程重启、执行恢复及原键重试后仍一致，排除集合参与幂等和配置身份。旧SELECTED以及不带排除的FILTERED请求、既有任务和断点仍可读取并保留原摘要语义；同键仅改变排除集合须拒绝冲突。订单来源保持只读。

<a id="ac-080"></a>
### AC-080 Ant Design日期时间筛选

给定订单查询表单，下单开始/结束时间使用Ant Design日期时间选择器，支持日期及秒级时间选择、单侧条件和清空。仅编辑控件不查询，点击查询才将界面香港时间转换为UTC提交；开始晚于结束或无效值阻止查询并显示关联错误。重置/历史恢复正确更新控件，提交中及UNKNOWN时控件不可编辑；同一香港时间在不同浏览器本机时区下生成相同UTC条件。

<a id="sc-015"></a>
### SC-015 全量选择质量门禁（草稿）

在记录了Node22、pnpm10.34.6、Java21和锁文件的本地环境中，全量选择及日期控件新增行为的单元/组件/契约/真实MySQL与文件范围测试、受影响回归和质量门禁通过，保留新增行为红灯与实现后绿灯证据；全量选择和反选的请求记录证明没有新增全量ID或逐页查询。此标准不新增性能专项或浏览器E2E门禁。


## 任务列表与暂停规格草稿

2026-10-14负责人要求准备任务界面规格，并明确“仅做列表/SSE/暂停，增删改先预留”。范围与以下新增标准的详细语义已随[任务规格0.3](../../specs/004-task-management/spec.md)于2026-10-17批准，[暂停ADR](../adr/0010-task-pause-control-barrier.md)已接受；测试阶段及六类缺口处理方案也已获批，当前生产实施已授权，见[审批记录](../../specs/004-task-management/tasks.md#审批记录)。失败后用户手动重试和用户继续亦不进入本期，原标准定义与历史证据保留。性能与超时/延时按负责人本轮指令不安排验证，项目级[规则草案](../rules/testing-efficiency-proposal.md)仍待批准；免验不计达标。

<a id="ac-081"></a>
### AC-081 任务列表权威快照

给定任务管理页查询任一分页或筛选，当快照返回时，列表条目、命中总数与任务版本来自同一MySQL一致性读取，并返回不受当前分页和筛选影响的环境活动版本及是否存在活跃任务；响应不含执行owner、客户载荷或物理文件路径。

<a id="ac-082"></a>
### AC-082 SSE快照衔接与版本合并

给定可见任务页已有列表快照，当建立真实SSE、收到stream-ready或重新连接时，系统执行一次桥接快照并合并期间收到的事件，旧任务版本、重复事件和旧查询响应不覆盖新状态；纯进度事件直接更新，不改变页码或稳定排序，影响筛选成员或总数的事件合并为权威当前页查询，不按每个进度事件查询、不注册周期轮询。

接受当前连接的空闲关闭事件后，页面执行一次当前查询的最终权威快照，补齐尚未到达的最后状态；无活动保持空闲，有新活动按快照建立连接，不注册周期查询。无效事件结构关闭连接并显示安全协议错误，不持续自动重试。

<a id="ac-083"></a>
### AC-083 暂停受理与安全停止

给定PENDING或RUNNING任务，当用户暂停且数据库事务确认提交时，未认领等待任务直接PAUSED并封存原投递权，已执行任务先PAUSING并建立控制屏障；只有安全停止证明或数据库证明无有效执行且建立隔离后才提交PAUSED。暂停先提交时旧执行者不得再登记新块、READY或终态；完成先提交时暂停返回状态冲突。重复同操作不重复迁移，不将暂停当失败，不丢失可信断点和实际进度，数据库不可读不确认消费。

<a id="ac-084"></a>
### AC-084 暂停状态展示与动作边界

给定任务页收到合法状态快照或事件，当状态为PENDING、RUNNING、PAUSING、PAUSED、SUCCEEDED或FAILED时，页面分别显示等待中、生成中、暂停中、已暂停、已完成、失败；前三种作为活跃通道判据，PAUSED不作终态，未结束状态不显示结束时间。本期仅等待中或生成中可暂停、仅成功可下载，其他状态禁用相应操作并说明原因；状态筛选包含新增状态，不显示预留的增删改、重试或继续入口，后端独立校验合法动作。未知状态不得映射为合法终态，安全提示且所有动作禁用。

<a id="ac-085"></a>
### AC-085 可靠进度通知与缓存降级

给定任务创建、认领、进度、终态、暂停或停止确认已提交，当通知异步投递时，可观察版本与进度Outbox同事务登记，独立通知只发布taskId及版本，不重投执行命令；发布确认使用版本比较，不删除并发更高待通知版本。各稳定API实例用各自持久队列读取不低于通知版本的摘要再广播，实际发送完成后才确认，失败保留通知；缓存缺失、落后或故障回源MySQL；数据库不可读保留通知，连接发送失败关闭并由客户端快照恢复，终态与空闲仍以MySQL裁决。

<a id="ac-086"></a>
### AC-086 任务查询与暂停输入保护

给定绕过前端的任务查询或暂停请求，当分页、枚举、UUID、控制版本、未知字段或暂停状态非法时，后端返回稳定安全错误且不留下部分业务变更；关键字参数化查询沿用任务编号/文件名口径。前端提交查询、重置或改页大小回第一页，手动刷新保页，成员变化使页越界时查询最后有效页；URL恢复合法已提交查询，旧请求不覆盖新查询，页面显示加载、空结果、失败及不可用原因。

<a id="ac-087"></a>
### AC-087 暂停结果不明与同操作找回

给定暂停发生连接中断或事务结果无法确认，当前端未得到明确结果时，不宣称已暂停或业务失败，保留原操作ID、目标与预期控制版本并阻止该行互斥提交；以同一操作重发可找回已提交回执，后端先判断操作回执再校验当前控制版本，同ID不同请求拒绝。确认后展示当前权威状态，不因后续进度或状态变化重新执行旧暂停；进度版本变化不单独导致控制前置条件失败。

<a id="sc-016"></a>
### SC-016 任务暂停安全闭环

在记录Java21、Node22、锁定依赖及已有真实MySQL/RabbitMQ/Redis隔离环境的本地功能验证中，等待暂停、执行中安全停止、完成/认领竞态、旧控制身份登记拒绝、重复操作和提交不明找回均具可判定证据；已暂停任务原编号、实际进度、可信断点和保护引用仍可读取，进程重启或原消息重交付不重新生成，也不登记虚假失败或成功。本标准不包含暂停生效时长、租约到期路径或用户继续能力。

## 装配校验与自动修复增量草稿

2026-10-17负责人明确要求将装配异常自动修复加入[任务规格](../../specs/004-task-management/spec.md)。以下新增语义与[修复ADR](../adr/0011-selective-block-repair-and-progress.md)已于2026-10-17随规格0.3批准进入测试先行；测试阶段与生产实施授权已取得；对本期显示进度的修正优先采用本增量，既有高水位和连续前缀的历史定义不被静默改写。

<a id="ac-088"></a>
### AC-088 装配文件与登记对账

给定正在执行且即将装配的任务，系统在装配入口核对完整分段清单、块登记及实际文件，在装配逐块读取至EOF及最终Excel关闭后继续校验；缺失、内容损坏、大小／摘要／行数／配置／游标或登记不匹配均可被识别并记录安全错误，未通过校验的结果不得成功发布。数据库不可读不等同记录缺失，SSE发送不逐次读取磁盘，校验入口后的损坏在后续读取或最终校验边界处理。

<a id="ac-089"></a>
### AC-089 同任务有界选择性自动重建

给定装配发现可恢复的不匹配，任务保持生成中，在原任务、原命令和有效执行身份内自动重试，保留所有匹配数据块（包括坏块之后的匹配块），仅重建不匹配分段；POI工作文件和Excel候选重新装配。缺文件或缺块登记时必须有可验证的独立区间及内容基线，重读源与原基线一致才登记替换；无恢复依据或源已改变则明确失败。修复轮次持久有界且不因崩溃清零，耗尽明确失败，不无限重试；暂停／失权后禁止继续登记，已暂停不自动修复，原受保护文件和记录不因修复删除。

<a id="ac-090"></a>
### AC-090 校验后的可信进度修正

给定完整对账已识别可复用与待重建数据，系统在开始重建前先事务提交匹配数据块行数之和作为当前可信已处理量，并随任务新版本经HTTP及SSE展示；该进度允许低于校验前值，坏段替换提交后只增加一次，旧事件／HTTP／缓存不得恢复旧高值。历史高水位不充当当前计数；非成功最多99%，仅成功采用事务提交后100%。仅工作文件损坏而数据块全可信时不扣减数据行数；纯进度及修复提示更新不重排、翻页或追加查询。

<a id="ac-091"></a>
### AC-091 重建黄色提示与生命周期

给定任务处于损坏文件重建或其后重新装配阶段，进度条后显示黄色信息图标，hover及键盘focus提示“正在重建损坏文件”，并提供相同可访问名称；不得只靠颜色说明。校验中说明正在校验，暂停中／已暂停切换相应重建暂停文案，成功移除提示，最终失败以安全错误展示且不再提示正在重建。刷新和重连依据权威持久字段恢复提示。

<a id="sc-017"></a>
### SC-017 选择性修复闭环

在已有真实MySQL、RabbitMQ、Redis及隔离小范围文件环境中，具备文件删除／损坏、块登记缺失但清单存在、恢复依据缺失、源变化、仅Excel候选损坏、修复耗尽、提交不明及暂停竞争的可判定证据；可恢复情况生成的最终文件行集合、顺序与内容基线一致，健康块身份不变，进度先修正再推进，HTTP/SSE及刷新后的提示一致。只验证功能与数据准确性，不含性能、超时、延时或租约到期测量。

## 用户继续与实时进度增量

2026-10-17负责人明确要求继续能力及真实自动推流，并预授权[005规格](../../specs/005-task-resume-and-live-progress/spec.md)完成后补测试、直接实施。本增量覆盖旧任务界面中不提供继续入口的范围限制，旧标准历史记录保留。

<a id="ac-092"></a>
### AC-092 用户继续与新执行权

给定PAUSED任务，用户显式继续且控制版本匹配时，同一事务将原任务转PENDING、递增控制/摘要版本、重开原命令投递权并登记回执及通知；重复操作返回当前摘要，跨请求/跨动作复用操作ID、错误版本及非PAUSED状态拒绝，无部分提交。结果不明可同ID找回。重新认领沿用原任务/命令且推进fence、采用当前控制版本，保留历史及修复预算，旧执行身份和旧投递token不得写入。

<a id="ac-093"></a>
### AC-093 用户继续前核验与部分收集恢复

给定显式继续的任务，执行者在继续收集或装配前核验数据库登记区间与实际数据块；未封存集合按断点前缀及末游标核验，完整集合按封存清单核验。任意位置健康块保留，缺文件、损坏或块登记缺失仅在有独立区间/内容基线时重建；无依据且已有登记进度明确失败，源变化明确失败，数据库未知不当作记录缺失。可信进度取核验健康行数、替换只累计一次，多余未登记文件不计入；部分集合修复后继续尾部，POI工作文件重新装配，原3轮预算不清零。

<a id="ac-094"></a>
### AC-094 真实自动进度到最终成功

给定正常启动的生产应用和实际SSE连接，无需手动调用发布方法，已提交中间进度和最终状态可经进度Outbox、MQ及HTTP事件自动到达；Redis缓存按版本更新且不替代MySQL权威。只有最终文件通过验证并在采用事务提交后，事件/列表显示SUCCEEDED和100%，文件可下载；未完成装配不得用计数满值伪造100%。不以页面轮询补偿自动推流缺失。

<a id="ac-095"></a>
### AC-095 继续交互与空闲通道恢复

给定PAUSED且服务端允许RESUME的任务，页面显示“继续”，确认后提交冻结的operationId/控制版本，互斥禁用重复操作；UNKNOWN时以同动作同请求找回。继续后即使原页无活动连接，也能从权威活动快照重建SSE；新版本降低进度、重建黄色说明及最终100%无需刷新即可显示，暂停中不提供继续、半成品不可下载。

<a id="sc-018"></a>
### SC-018 继续与实时通知正确性闭环

在Java21、Node22及已有MySQL/RabbitMQ/Redis隔离环境中，记录继续控制、部分文件选择性修复及真实自动SSE至最终采用/下载的可复现证据；健康块身份保持、最终行集合/顺序/内容与只读来源一致，前端可接收可信进度回退及成功100%。保留红灯与绿灯、受影响回归和质量门禁证据，不包含性能及超时延时测量。

## 任务统一删除增量草稿

2026-10-18需求确认：任务页只增加一个“删除”入口，由同一个接口读取任务权威状态并在服务端区分运行中删除与终态删除。用户已明确要求按`006-task-deletion`规格直接测试、自检和开发；为保证运行中删除的迟到消息、Worker租约和文件清理可追溯，本增量采用删除控制屏障、持久删除操作回执和任务墓碑。

<a id="ac-096"></a>
### AC-096 统一删除入口与服务端分流

给定任务列表中的任意可删除任务，页面只显示一个“删除”按钮；用户确认后调用同一个删除接口。服务端必须读取最新任务状态并在同一裁决流程中区分运行中删除和终态删除，客户端不得根据旧列表状态选择不同接口或绕过服务端状态校验；未知状态、已删除任务和版本不匹配请求均返回稳定安全错误。

<a id="ac-097"></a>
### AC-097 运行中删除建立控制屏障

给定任务处于`PENDING`、`RUNNING`、`PAUSING`或`PAUSED`，删除请求提交后，服务端必须先持久化删除请求、递增控制版本并关闭或撤销尚未执行的投递权；有效Worker在下一次控制检查中停止继续读取、写入块、登记产物或提交成功/失败结果。暂停中的任务不得被恢复或继续执行，删除请求不被伪造为导出失败。

<a id="ac-098"></a>
### AC-098 运行中删除安全停止后清理

给定运行中删除已被受理，系统只有在数据库证明没有有效执行租约或Worker提交安全停止证明后，才进入清理阶段；清理前保留删除操作回执、任务墓碑和必要的消息身份。Worker、dispatcher或迟到消息的提交不能越过删除屏障生成文件、改变任务结果或重新打开投递权。

<a id="ac-099"></a>
### AC-099 终态删除清理任务数据

给定任务处于`SUCCEEDED`或`FAILED`且没有有效执行租约，删除接口将任务标记为删除中并安排任务专属数据清理；清理完成后必须删除任务根记录及其关联的幂等、投递、执行、断点、数据块、修复记录、产物引用和进度通知记录，并删除任务专属物理文件。清理失败可重试，不得删除仍被其他有效引用保护的文件或记录。

<a id="ac-100"></a>
### AC-100 删除操作幂等与结果不明找回

给定客户端因超时、断线或重复点击重复提交同一删除操作，服务端按操作标识和请求摘要返回同一删除回执，不重复发起取消、清理或文件删除；结果不明时客户端不宣称成功或失败，可使用原操作标识找回当前权威结果。相同操作标识携带不同任务或请求摘要必须拒绝。

<a id="ac-101"></a>
### AC-101 删除后的列表、下载与实时事件

给定任务进入删除中或已清理状态，任务列表不再把它作为正常任务展示，查询总数和分页保持一致；下载、暂停、继续和重试均被拒绝；删除操作产生的活动版本和实时事件不能使已删除任务重新出现在列表，旧事件或旧查询响应不得覆盖当前结果。

<a id="ac-102"></a>
### AC-102 删除失败与恢复可见性

给定消息、数据库或文件存储依赖不可用，系统保留删除墓碑、操作回执和待清理记录，向客户端返回安全的处理中或暂不可用结果；恢复后可继续清理，不把部分清理误报为完成，也不因清理失败恢复任务执行或下载能力。

<a id="ac-103"></a>
### AC-103 任务业务记录硬删除

给定删除清理成功，`export_tasks`及任务专属业务子表中不再存在该任务的可查询业务记录；任务列表、下载、暂停、继续和重试均不能通过任务编号恢复或操作该任务。为处理迟到消息而保留的独立技术墓碑、操作回执或清理审计记录不属于任务业务记录，必须与任务表解耦并限制字段，不得保存客户载荷、文件路径或可下载数据。

<a id="sc-019"></a>
### SC-019 统一删除安全闭环

在Java21、Node22及已有真实MySQL、RabbitMQ、Redis和隔离文件环境中，保留统一删除接口从运行中控制屏障、Worker安全停止、迟到消息裁决、终态数据库业务记录硬删除、物理文件清理、操作幂等、提交不明找回和SSE列表收口的可复现证据；清理失败可恢复且不产生重复文件、孤儿执行或已删除任务复活。本标准不包含性能专项或固定删除完成时延。

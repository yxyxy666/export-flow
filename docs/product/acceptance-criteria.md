## 订单查询与选择

<a id="ac-001"></a>
### AC-001 初始查询

给定用户进入订单管理页面，当页面加载完成时，那么页面展示筛选区、操作区、订单表格和分页区，并立即按无筛选条件查询第一页，分页默认每页 20 条。

<a id="ac-002"></a>
### AC-002 组合筛选

给定用户填写一个或多个筛选条件，当点击“查询”时，那么系统按照全部已填写条件的“并且”关系查询，并从第一页展示结果。

<a id="ac-003"></a>
### AC-003 重置

给定用户已经设置筛选条件或勾选订单，当点击“重置”时，那么系统清空筛选条件和已选订单，恢复第一页及每页 20 条，并立即按无筛选条件查询第一页。

<a id="ac-004"></a>
### AC-004 订单分页

给定查询结果超过一页，当用户切换页码或将每页数量设置为 20、50、100 时，那么系统展示对应页面的数据、当前页、每页数量和总条数；修改每页数量后返回第一页。

<a id="ac-005"></a>
### AC-005 范围校验

给定开始时间晚于结束时间，或最小金额大于最大金额，当用户发起查询时，那么系统阻止查询并给出可理解的校验提示。

<a id="ac-020"></a>
### AC-020 跨页选择生命周期

给定用户已经勾选订单，当切换分页时，那么系统保留已勾选订单；当用户修改筛选条件并重新查询时，那么系统清空此前勾选并展示新查询结果。

<a id="ac-021"></a>
### AC-021 订单号精确匹配

给定用户输入订单号，当执行查询时，那么系统仅返回订单号完全相等的订单。

<a id="ac-022"></a>
### AC-022 时间边界与时区

给定用户按 `Asia/Hong_Kong` 选择精确到秒的下单时间范围，当执行查询时，那么系统将开始和结束时间转换为 UTC，并包含恰好等于两个边界的订单。

<a id="ac-023"></a>
### AC-023 金额边界

给定用户输入最小金额和/或最大金额，当执行查询时，那么系统包含金额恰好等于已填写边界的订单。

<a id="ac-024"></a>
### AC-024 订单稳定排序

给定多条订单具有不同下单时间或相同下单时间，当展示查询结果时，那么系统按下单时间倒序、再按订单唯一 ID 倒序稳定排列。

<a id="ac-033"></a>
### AC-033 订单选择工具

给定订单列表有多页，当用户在不同页面勾选订单时，那么已选数量和订单集合跨页保留；点击“全选当前页”“反选当前页”或“清空已选”时，只按按钮语义更新选择集合。

<a id="ac-034"></a>
### AC-034 订单排序切换

给定订单表格已展示，当用户切换下单时间排序时，那么结果按升序或降序稳定排列，相同时间按订单 ID 同方向排序，并回到第一页。

<a id="ac-035"></a>
### AC-035 订单关键字搜索

给定用户输入关键字并查询，当关键字匹配订单号、客户姓名或手机号任一字段时展示该订单；匹配不区分英文大小写，并与其他筛选条件使用“并且”关系。

## 创建导出任务

<a id="ac-006"></a>
### AC-006 导出已选订单

给定用户至少勾选一笔订单，当点击“导出已选”、选择导出字段并确认时，那么系统基于已选订单和所选字段创建一个异步导出任务。

<a id="ac-007"></a>
### AC-007 无选择时禁用

给定用户没有勾选任何订单，那么“导出已选”不可用，并显示不可用原因。

<a id="ac-008"></a>
### AC-008 导出筛选结果

给定当前筛选结果不为空，当点击“导出筛选结果”、选择导出字段并确认时，那么系统基于符合当前筛选条件的全部订单和所选字段创建异步导出任务，导出范围不受当前页限制。

<a id="ac-009"></a>
### AC-009 空结果时禁用

给定当前筛选结果为空，那么“导出筛选结果”不可用，并显示不可用原因。

<a id="ac-010"></a>
### AC-010 创建幂等

给定系统收到多个携带同一 `Idempotency-Key` 的创建导出任务请求，那么这些请求只对应一个导出任务，不产生重复文件。

<a id="ac-011"></a>
### AC-011 大任务异步接受

给定导出范围包含十万条以上且不超过 200,000 条订单，当用户成功提交导出时，那么系统接受任务并允许用户通过导出任务列表查看后续状态，而不是等待文件在订单列表请求中直接返回。

<a id="ac-019"></a>
### AC-019 导出上限

给定导出范围超过 200,000 条订单，当用户尝试创建任务时，那么系统不创建任务，并提示当前数据量、单次上限以及缩小筛选范围或减少勾选数量。

<a id="ac-025"></a>
### AC-025 创建成功跳转

给定用户成功创建导出任务，当接口返回新任务时，那么系统清空已选订单并自动进入导出任务页面。

<a id="ac-030"></a>
### AC-030 创建失败保留状态

给定创建导出任务请求失败，当系统展示错误时，那么用户仍停留在订单管理页面，筛选条件、导出字段和已选订单保持不变。

<a id="ac-050"></a>
### AC-050 创建成功以事务提交为前提

给定首次创建导出任务，当后端向前端返回创建成功和任务 ID 时，那么 MySQL 中必须已经提交可按该 ID 查询的任务及与其同事务创建的命令 Outbox；事务明确回滚时不得返回创建成功。响应到达时 Outbox 可能已被后台标记为 `SENT`；创建成功不要求 RabbitMQ 已收到消息，也不要求文件已生成。

<a id="ac-051"></a>
### AC-051 创建结果不明时找回同一任务

给定创建请求超时、连接中断或事务提交结果无法确认，当用户按原请求内容和原 `Idempotency-Key` 重试时，那么前端在得到明确结果前不宣称创建成功或失败，并保留筛选条件、导出字段和已选订单；后端若核对到同键同请求已提交，返回同一任务的当前摘要，不创建第二个任务或文件。

## 补投自动失败与可靠性

<a id="ac-052"></a>
### AC-052 未确认投递的总窗口自动失败

给定任务及原命令 Outbox 已提交，当数据库时间达到创建事务持久化的受理时间加 10 分钟，且任务仍为 `PENDING`、原命令未 `SENT` 且未关闭时，后台自动扫描须在同一事务将任务置为 `FAILED`、记录结束时间与 `TASK_DISPATCH_TIMEOUT`、关闭原命令并撤销领取权，无需人工批准。扫描启动周期为 5 秒，启动恢复时也检查；不受退避、有效租约或 MQ 是否可用影响。数据库或后台不可用时允许延迟提交，但恢复后须处理到期记录，不重置截止时间。用户看到“任务投递超时，未开始执行。请重试或重新创建任务。”；原记录保留，失败重试沿用 [`AC-016`](#ac-016) 的新任务语义，新建使用新提交幂等标识，重放旧标识只返回原失败任务。

<a id="ac-053"></a>
### AC-053 超时、认领与发布确认的并发裁决

给定超时失败与 Worker 认领或 dispatcher 标记发送并发，当数据库串行化裁决时，未发送且仍待执行的任务到期后不得再获得新的认领或发送成功标记；期限内已成功认领、已提交 `SENT` 或已终态的任务不得被该投递超时规则改为失败。失败与 Outbox 关闭提交后，迟到确认不能重开记录，旧消息只能在核对已提交终态后确认消费，不生成文件或改变原失败结果；数据库不可读时不提前确认。

<a id="ac-054"></a>
### AC-054 单条坏记录不阻断正常补投

给定同批 Outbox 包含载荷序列化失败、不支持的版本或不可路由的单条记录，当该记录处理失败时，其诊断与调度被保留，不删除或永久跳过，其他可处理记录继续投递且已成功标记不回滚；坏记录满足总窗口条件后自动失败。共享数据库或 MQ 连接故障须与单条错误区分，恢复后可继续扫描。

<a id="ac-055"></a>
### AC-055 崩溃接管保持尝试历史和退避

给定投递领取事务已提交，当 dispatcher 在发布或失败回写前崩溃，或记录被过期接管时，那么已持久化的尝试历史和截止时间不得重置，接管须同时满足领取权到期与持久退避到期，失败回写缺失不能绕过退避；到总截止时间后由自动失败路径处理，不因下一次重试时间更晚而无限等待。

<a id="ac-056"></a>
### AC-056 已确认命令的队列保留

给定命令已可靠存储在获批目标任务队列并标记 `SENT`，当 broker 正常重启或队列达到配置容量上限时，那么未消费命令不得因消息 TTL、自动删除或淘汰旧消息而静默丢失，容量不足须拒绝新发布且不能错误标记 `SENT`；队列有效策略不符合保留要求时须阻止不合规发布成功标记并告警。灾难性损坏及人为误删不作为本条的正常恢复保证，不据排队时长自动复制或失败任务。

## 查看与处理导出任务

<a id="ac-012"></a>
### AC-012 持续显示任务进度

给定任务处于等待中或生成中，当用户查看导出任务列表时，那么系统显示任务状态以及已处理条数、总条数和百分比，并持续更新进度。

<a id="ac-013"></a>
### AC-013 下载成功文件

给定任务已完成，当用户点击“下载”时，那么系统向用户提供对应的 Excel 文件。

<a id="ac-014"></a>
### AC-014 非成功任务禁止下载

给定任务处于等待中、生成中或失败状态，那么下载操作不可用，并显示不可用原因。

<a id="ac-015"></a>
### AC-015 成功任务元数据

给定任务已完成，当用户查看任务时，那么系统显示文件名、结束时间和文件大小。

<a id="ac-026"></a>
### AC-026 任务状态筛选

给定用户选择全部、等待中、生成中、已完成或失败状态，当执行任务筛选时，那么系统从第一页展示对应状态的任务；“全部”不附加状态条件。

<a id="ac-027"></a>
### AC-027 任务分页

给定导出任务超过一页，当用户切换页码或将每页数量设置为 20、50、100 时，那么系统展示对应页面、当前页、每页数量和总条数；默认每页 20 条，修改每页数量后返回第一页。

<a id="ac-028"></a>
### AC-028 任务稳定排序

给定导出任务列表正在展示，当列表首次加载或进度数据刷新时，那么任务按创建时间倒序、再按任务唯一 ID 倒序稳定排列。

<a id="ac-031"></a>
### AC-031 刷新保持当前页

给定用户正在查看非第一页任务，当普通进度数据刷新完成时，那么系统仍展示刷新后的当前页。

<a id="ac-036"></a>
### AC-036 活跃任务优先

**状态：2026-10-07已撤出；保留原意，编号不复用。** 决定沿用 [`AC-028`](#ac-028) 默认排序，本条不进入实施范围。

给定任务列表包含不同状态，当使用默认排序时，那么等待中和生成中的任务排在终态任务之前；生成中按进度降序排列；同组同进度按创建时间倒序、任务 ID 倒序稳定排列。

<a id="ac-037"></a>
### AC-037 进度排序

**状态：2026-10-07随 [`AC-036`](#ac-036) 撤出；保留原意，编号不复用。** 当前不提供本条所描述的进度排序。

给定用户切换进度排序，当选择升序或降序时，那么任务按百分比排序，并以默认状态优先级、创建时间和任务 ID 作为稳定次序；操作后回到第一页。

<a id="ac-038"></a>
### AC-038 任务关键字搜索

给定用户输入关键字并查询，当关键字匹配任务编号或文件名时展示该任务，并与状态筛选使用“并且”关系。

<a id="ac-016"></a>
### AC-016 失败任务重试

给定任务失败，当用户执行重试时，那么系统按原任务的导出范围和字段配置创建一个具有新任务编号的任务，并保留原失败任务记录供后续查看；初始化后的订单数据只读，因此原筛选范围不会因数据变化而漂移。

<a id="ac-017"></a>
### AC-017 非失败任务禁止重试

给定任务处于等待中、生成中或已完成状态，那么重试操作不可用，并显示不可用原因。

<a id="ac-018"></a>
### AC-018 永久保留

给定任意时间创建的导出任务，当用户查看任务记录和已完成任务的文件时，那么记录与文件仍然保留，已完成任务仍可下载。

<a id="ac-032"></a>
### AC-032 重试后返回第一页

给定用户成功重试失败任务，当新任务创建完成时，那么系统返回导出任务列表第一页，并保留原失败任务记录。

<a id="ac-049"></a>
### AC-049 已发送任务的队列交付与认领

给定命令 Outbox 已确认发送而导出任务仍为 `PENDING`，当消息在队列等待或已交付但尚未被 Worker 在 MySQL 中认领时，系统不得仅因等待超过固定时长就自动补投同一任务或将其标记为 `FAILED`；Worker 断连且未确认消费的消息可重新交付，收到消息的 Worker 只有成功提交 `PENDING -> RUNNING` 才能生成文件，重复消息不得生成第二份文件。Worker 仅收到消息时不得提前确认消费，业务终态已提交或权威状态证明无需处理后才能确认消费。

## 按需 SSE 生命周期

<a id="ac-039"></a>
### AC-039 活跃时更新、终态后停止

给定任务页可见且存在 `PENDING` 或 `RUNNING` 任务，当进度通道启动时，那么进度持续更新且不回退；全部任务进入终态后通道关闭。mock 阶段验证相同生命周期，但不得声称真实 SSE 已完成。

<a id="ac-040"></a>
### AC-040 单例通道唤醒

给定任务页可见且当前没有活跃进度通道，当创建或重试产生新任务、页面重新可见或执行刷新发现活跃任务时，那么系统建立一个通道；同一时刻不得存在重复通道。页面隐藏期间不得仅因新任务产生而建立通道。

<a id="ac-042"></a>
### AC-042 服务端显式空闲标记

给定真实 SSE 通道中的任务均已进入终态，当后端经过空闲宽限期并再次确认没有活跃任务且活动版本未变化时，那么后端发送 `stream-idle` 标记并结束响应；前端收到属于当前通道且没有更新活动的标记后主动关闭 `EventSource`，不得因该次正常空闲关闭自动重连。

<a id="ac-043"></a>
### AC-043 创建与空闲判定竞态

给定创建或重试新任务与后端空闲判定并发发生，当两者无法证明严格先后或创建/重试提交使活动版本变化时，那么新任务优先，后端取消本次 `stream-idle`，经过宽限期后重新判断；不得用前后端墙上时间或相等时间戳决定顺序。

<a id="ac-044"></a>
### AC-044 空闲关闭后重新开启

给定 SSE 已因 `stream-idle` 正常关闭，当本客户端创建或重试成功、任务页首次进入或恢复可见、浏览器恢复联网、手动刷新，或同浏览器其他标签页通知新任务时，那么前端执行一次快照查询并在存在活跃任务时重新建立唯一 SSE 通道；异常断线按受控退避重连，不视为正常空闲关闭。系统不得注册固定或低频轮询。

<a id="ac-057"></a>
### AC-057 两个静态业务占位页

给定基础骨架已启动，当用户进入订单路由或任务路由时，那么左侧菜单分别提供“订单管理”和“任务管理”，内容区分别仅展示对应的中文页面名称，不展示筛选、表格、分页、导出、下载、任务状态或其他业务操作。

<a id="ac-058"></a>
### AC-058 目录与文件职责可核对

给定基础骨架交付，当按获批计划核对仓库时，那么前后端目录和本期要求创建的文件均存在且职责明确；仅预留的业务文件包含中文职责说明而无业务实现，前端构建不导入这些业务占位文件，后端占位文件不会被宣称为可运行服务。

<a id="ac-059"></a>
### AC-059 静态骨架不依赖后端

给定后端及 MySQL、RabbitMQ、Redis 均未启动，当启动并操作前端静态骨架时，那么两个占位页和菜单仍可使用；页面不发起业务 API、SSE 或轮询请求，也不执行导出、下载或中间件连接。

### AC-061 后端独立输入与范围校验

### AC-063 单任务受理回执

给定创建成功或同键找回已创建任务，当前端进入任务管理路由时，可按任务 ID 读取 MySQL 权威摘要并展示范围数量、有序字段、状态、实际进度及安全错误；手动刷新执行一次快照查询，不注册定时轮询或假 SSE。不存在的任务显示可理解提示；本阶段回执不声称完整任务列表或文件下载已完成。

### AC-064 同幂等键不同请求拒绝

给定同一个幂等键已登记，当请求的规范化范围或有序字段不同于原请求时，后端返回 409 与 IDEMPOTENCY_KEY_REUSED，不创建新任务或返回原任务掩盖冲突；语义等价的范围输入仍找回同一任务，字段顺序变化不视为等价。

<a id="ac-065"></a>
### AC-065 查询恢复与客户输入保护

给定已提交订单查询，当用户刷新或前进后退时，系统从 URL 恢复合法的非敏感筛选、分页与排序，非法项规范化并提示；可能包含客户姓名或手机号的关键字只保存在页面内存，不写入 URL、长期存储或日志，刷新或历史导航时清空并提示需重新输入，选择集合不与恢复后的另一查询混用。

<a id="ac-066"></a>
### AC-066 Worker 权威认领与空生成器隔离

**状态：2026-10-07 因本次规格纳入真实 Excel 已撤出候选范围；原意保留，编号不复用。**

**架构前提：执行权子集须在 ADR 归属处明确审批；本条不批准完整暂停、断点或异常恢复协议。**

给定本期 Worker 编排在已批准执行架构下接受测试命令，只有 MySQL 认领事务已确认并建立有效 owner、隔离代次及租约后才能调用可用生成器；重复消息、失权、提交不明或数据库不可读时不得重复推进或提前确认消费。生成器不可用时不认领活跃任务，已提交终态可核对后确认消费；测试替身返回可信成功或明确失败时先提交合法终态再确认。空函数和测试替身不构成真实文件验收证据。

<a id="ac-067"></a>
### AC-067 真实 Excel 异步生成与下载闭环

给定用户已成功提交合法导出申请，当后台消费者取得已确认执行权后，系统真实读取固定范围并生成可正常打开的.xlsx，字段、顺序、表头、中文枚举、未知回退、客户原值、金额精度及香港时间与任务配置和页面口径一致；只有文件关闭、校验、安全发布及权威成功引用提交后才提供下载，不返回未实现或模拟成功。

<a id="ac-068"></a>
### AC-068 异常接管、断点续写与旧执行者隔离

**状态：2026-10-07产品结果已确认，架构子集见 [ADR-0008](../adr/0008-worker-execution-lease-and-recovery.md)；用户暂停或显式恢复不纳入当前MVP。**

给定任务执行期间发生进程退出、失权或提交结果不明，当原未确认命令重新交付时，系统只在MySQL授权条件满足后取得新owner与隔离代次；优先校验并续写可信连续数据块，采用可信就绪产物，无可信断点时只有证明安全重复才建立新数据代次。旧执行者不得覆盖新断点、进度或唯一结果；恢复不创建第二个任务，预算仅成功接管扣减，耗尽或明确不可恢复时合法事务提交失败，确认消费晚于该终态。

<a id="ac-069"></a>
### AC-069 持久断点、文件对账与安全清理

给定数据块、就绪产物或成功文件已被权威记录引用，当进程重启、生成中断或孤儿清理发生时，这些引用仍可访问且不得按年龄、租约过期或Worker不活跃删除；文件存在但无可信登记不得当作成功。采用与清理通过数据库串行裁决互斥，只有无有效执行及任何保护引用的孤儿才可清理；成功文件与任务永久保留，成功提交不明先核对而不删除结果。

<a id="ac-070"></a>
### AC-070 单任务结果回执与直接下载

给定任务已创建，当用户进入其任务管理回执或手动刷新时，系统读取MySQL权威摘要，展示范围、字段、状态、实际进度、错误及成功文件名、大小和结束时间；成功任务可用同源直接链接下载，其他状态禁用并显示原因。手动刷新每次只查一次，不注册定时轮询或假SSE；本回执不声称完整任务列表或持续通知已经完成。

<a id="ac-071"></a>
### AC-071 增量临时写入与正式结果转换

给定真实Excel正在生成，当一个数据批次写完时，已完成行及缓冲写入该工作簿的磁盘临时文件，内存不累计保留全部行；此时不提供未完成内容作为正式结果。全部内容完成、输出关闭及校验通过后，临时结果通过同卷原子改名转换为正式.xlsx，随后按权威就绪与成功事务提供下载；刷盘、校验或改名失败时不登记成功、不下载半成品，已登记恢复数据仍受保护。

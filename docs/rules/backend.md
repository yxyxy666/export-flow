# 后端工程规则

## 1. 文档定位

本文定义 Export Flow 后端长期有效的架构、接口、事务、异步任务、文件、SSE、可靠性和质量规则。单次功能的字段、示例、验收映射和任务写入对应 `specs/<feature-dir>/`。

- 产品基线：[`order-export-prd.md`](../product/order-export-prd.md)。
- 验收基线：[`acceptance-criteria.md`](../product/acceptance-criteria.md)。
- 架构决策：[`ADR-0003`](../adr/0003-application-stack-and-local-runtime.md)、原 [`ADR-0004`](../adr/0004-redis-streams-and-backend-processing.md)、待评审的 [`ADR-0005`](../adr/0005-rabbitmq-task-queue.md) 和 [`ADR-0006`](../adr/0006-backend-stack-and-progress-cache.md)。目标方案未获批准前不得实施。
- 相关规则：[`testing.md`](testing.md)、[`build.md`](build.md)、[`container.md`](container.md)、[`naming.md`](naming.md)。
- 待确认事项：[`decisions-pending.md`](../decisions-pending.md)。

本期是本地学习项目，不启用登录、认证授权、权限审计、远程部署或对象存储；按截图整理的待评审方案，RabbitMQ 承担任务队列，Redis 只做进度缓存，MySQL 是进度事实源，SSE 对前端广播。该范围不豁免输入校验、幂等、事务、消息可靠性、并发、文件安全、错误处理和测试门禁。

## 2. 技术边界（本次修订待评审）

- Java 21、Spring Boot 3、Maven Wrapper。
- Spring MVC 接收 API 请求、校验 DTO 并统一映射异常；MyBatis 提供动态 SQL 和显式查询，Flyway 管理版本化 schema 迁移。具体依赖版本和映射结构在初始化前确认。
- MySQL 8.4 LTS；本地、测试和容器环境不得用 H2 等不同数据库替代关键持久化行为。
- MySQL 8.4 LTS 是永久业务状态和 outbox 的事实源；业务表使用 InnoDB，字符集使用 `utf8mb4`，数据库连接和会话时区使用 UTC，并启用严格 SQL 模式。
- RabbitMQ 承担任务命令队列；worker 消费语义为至少一次。Redis 8 只缓存最新进度，不使用 Streams。
- MySQL 事务 outbox 负责可靠衔接任务创建与 RabbitMQ 命令投递。进度状态先提交 MySQL；进度通知如何跨后端实例广播须另行审批，不能把 Redis 缓存当作可靠事件存储。
- Apache POI `SXSSF` 流式生成 `.xlsx`；文件写入本地挂载目录，元数据和任务状态写入 MySQL。
- 目标 Docker Compose 包含前端、后端、MySQL、RabbitMQ 和 Redis；数据库、生成文件及消息基础设施数据分别使用命名卷持久化。RabbitMQ 和进度缓存部分待 ADR 评审。
- API 使用 `/api/v1` JSON REST，OpenAPI 是机器可读契约；文件下载使用同源直接链接。
- 任务进度只使用 SSE 实时推送，不使用固定或低频轮询。

MyBatis、Flyway 和 Redis 进度缓存是本次参考图引入的待评审选型，见 [`ADR-0006`](../adr/0006-backend-stack-and-progress-cache.md)；Spring SSE 适配器、静态检查插件及具体超时参数也须在实现前确认。

## 3. 架构与依赖方向

```text
api/transport -> application -> domain
                         -> ports
infrastructure ------------^
```

- `api/transport`：HTTP/SSE 协议、DTO、结构校验和错误映射，不承载业务决策。
- `application`：编排查询、创建、outbox 发布、消费、生成、重试和下载用例，定义事务与消息确认边界。
- `domain`：任务状态机、导出范围、字段选择、幂等和进度不变量；不依赖 Spring、HTTP、SQL 或 POI。
- `ports`：持久化、时钟、ID、文件、任务命令和进度事件接口。
- `infrastructure`：MyBatis/MySQL、RabbitMQ、Redis 进度缓存、文件系统、POI、调度器和 SSE 适配器。

依赖只能由外向内。控制器不得直接访问 repository，worker 不得绕过 application 用例修改任务，数据库实体和 API DTO 不得直接充当领域模型。

## 4. API 与契约

- OpenAPI 明确请求、响应、分页、枚举、错误体、HTTP 状态码和示例；契约变化必须先更新规格与契约测试。
- 输入在传输边界做结构和白名单校验，在 application/domain 层再次保护业务不变量；不得只依赖前端校验。
- Spring MVC 控制器将请求 DTO 映射为用例输入；统一异常处理区分参数错误、资源不存在、幂等冲突、依赖不可用和内部错误，不把数据库或消息中间件异常直接返回浏览器。
- 错误体至少包含稳定的 `code`、安全的 `message`、可选字段错误和 `requestId`，不得返回堆栈、SQL、内部路径或敏感数据。
- 列表分页从 1 开始，页大小仅允许 20、50、100；排序显式包含稳定 ID 作为最后一项。
- API 时间使用带 `Z` 的 UTC ISO 8601；页面、Excel 和文件名需要人类时间时转换为 `Asia/Hong_Kong`。
- 金额在协议中使用两位小数的十进制定点字符串，在 Java 中使用 `BigDecimal` 并明确舍入规则；不得使用 `double/float` 承担业务金额计算。
- 协议枚举在边界集中映射。未知值返回稳定协议错误或按已批准的兼容策略处理，不得静默改成另一业务状态。
- 下载接口只允许成功任务，校验数据库元数据与实际文件，安全生成 `Content-Disposition`，防止 CRLF、路径穿越和任意文件读取。

## 5. 幂等、事务与一致性

- 创建导出任务必须携带 `Idempotency-Key`。同一次传输重试复用键；用户新建导出或重试失败任务使用新键。
- 幂等键、规范化请求摘要和任务 ID 在同一事务中持久化，并由唯一约束保护；不能仅靠“先查询后插入”。
- 相同键和相同请求返回同一任务；相同键但不同请求的错误码和 HTTP 状态尚待审批。
- 创建任务时固化导出范围、命中数量和有序字段列表。`SELECTED` 保存不可变订单 ID；`FILTERED` 保存不含分页的筛选快照。
- 任务、幂等结果和待发布 outbox 事件必须在同一 MySQL 事务中提交。outbox 事件包含稳定事件 ID、聚合 ID、类型、版本、载荷、创建时间、发布状态和尝试信息。
- 服务端在创建事务中重新校验命中数量和 200,000 上限。前端计数不能作为权威判断。
- HTTP 请求事务必须短小；不得在数据库事务中生成 Excel、等待 SSE、执行长时间文件 IO 或做无界重试。
- 状态转换只能为 `PENDING -> RUNNING -> SUCCEEDED|FAILED`。重试创建新任务，不修改或回退原任务。
- 状态、进度、文件元数据和错误摘要的更新满足“终态不回退、进度不减少、处理数不超过总数”的条件更新或版本校验。原进度 outbox 与 Redis Stream 方案须随 SSE 广播机制重新评审，不得把缓存更新当作可靠消息投递。

## 6. Outbox、RabbitMQ 与 Worker

- outbox dispatcher 有界批量读取未发布的任务命令，发布到 RabbitMQ，取得发布确认及正确路由确认后条件更新 outbox 为已发布。发布失败保留事件并有界退避重试。进度通知的发布机制尚待确认，不得默认与工作队列共用竞争消费。
- dispatcher 崩溃可能导致同一 outbox 重复发布，因此消息 ID、worker 和状态转换必须幂等，不能依赖“只发布一次”。
- worker 从 RabbitMQ 领取任务消息。多个 worker 竞争同一任务时，只允许一个通过 MySQL 条件更新把 `PENDING` 声明为 `RUNNING`。
- RabbitMQ 任务消息只携带稳定任务 ID、事件 ID、类型、版本和必要追踪信息；worker 从 MySQL 读取权威任务快照，不把完整敏感业务载荷复制到队列。
- Excel 生成不持有 MySQL 行锁。worker 在有界事务中声明任务，提交后生成文件，再在新事务中提交进度或终态。
- 只有任务成功或确定失败并已持久化终态，或权威状态证明消息无需处理后，才手动确认 RabbitMQ 消息。重复、已终态或已由其他 worker 有效持有的消息按规则确认或重新投递，不能重复生成文件。
- 消费者中断后的 RabbitMQ 重新投递须结合 MySQL 任务状态和 worker 租约恢复；最大尝试次数耗尽后进入可诊断失败/死信流程，具体策略待审批。
- 每次尝试须保留可诊断的尝试次数和安全失败分类；人工重试失败任务创建新任务，不能清空原任务的审计记录。租约过期不等于文件可直接重复生成，恢复前须检查旧 worker 和临时/正式文件状态。
- 调度批次、并发数、退避、租约、最大尝试次数、队列持久化和死信保留均使用有界配置。
- 并发判断以 MySQL 提交顺序、版本和租约为准，不比较客户端时间戳，也不使用 Redis 分布式锁替代数据库状态机。
- 单任务异常不得停止 dispatcher、RabbitMQ 消费者或后续任务处理。

## 7. Excel 与文件生命周期

- 使用 `SXSSF` 有界行窗口流式写入，逐页或分批读取订单；不得把最多 200,000 行全部加载进 JVM 内存。
- 导出查询使用创建时固化的范围快照、稳定排序及 Keyset 分页批量读取；不得因偏移量变大而退化，也不得漏行或重复行。初始化后的订单只读；将来订单可写时必须重新定义快照一致性。
- 先写任务专属临时文件，完成 workbook 关闭、校验和文件发布后才能把任务置为 `SUCCEEDED`。
- 文件发布优先采用同一文件系统内的原子移动；不支持时必须记录并测试降级策略。
- 失败时关闭 POI/流资源并清理该任务临时文件；不得删除已成功发布且要求永久保留的文件。
- 文件路径由服务端稳定 ID 映射，不接受用户提供的目录或物理路径。显示文件名与物理文件名分离。
- 定期清理仅针对可证明已失效的任务专属临时文件；清理条件、宽限期和与正在生成任务的并发保护须在规格中明确，永久保留的正式文件不纳入清理。
- 下载使用流式响应，不把完整文件读入堆；文件缺失、状态不允许和 IO 失败必须可区分。

## 8. SSE 与进度发布

- 真实 SSE 的链路说明见 [`DATA-FLOW.md`](../../DATA-FLOW.md)；原契约草案已撤回，重新制定并获批前不得实现。
- 进度只通过 SSE 推送，不设置任何固定或低频轮询。进入页面、恢复可见、恢复联网和手动刷新可以执行一次性快照查询，但不得注册周期性查询。
- SSE 广播覆盖当前单一环境中全部未完成任务，不按列表当前页过滤。本期没有认证，不声明用户或租户隔离。
- worker 在 MySQL 事务中提交任务状态/进度。提交后尽力更新带版本的 Redis 最新进度缓存；缓存不可用不能回滚 MySQL，读取缺失或过期时回 MySQL。进度 outbox 是否继续保留及其发布目标待 ADR 评审。
- Redis 缓存键按环境和任务 ID 隔离，写入须比较状态版本以防迟到更新覆盖新进度；缓存有效期和容量待审批。任务状态、下载权限和重试资格始终由 MySQL 判定。
- SSE 适配器向本实例连接广播最新进度；跨后端实例的通知、在线漏通知补偿和顺序规则待审批，不能用任务工作队列的竞争消费代替广播。
- Redis 缓存不是事件历史。首次连接、异常断线和恢复时执行一次 MySQL 快照回补，不使用 Redis Stream ID 或固定轮询；SSE 事件 ID 与版本/回补语义须在契约中重新定义。
- 后端确认没有活跃任务时，不直接静默断开；按已批准宽限期复核活动版本后发送 `stream-idle`，再刷新并结束响应。
- 创建/重试与空闲判断并发时，以权威活动版本和活跃集合复核；无法证明严格先后时新活动优先。
- 后端主动结束响应后，前端收到有效 `stream-idle` 必须调用 `EventSource.close()`，避免浏览器自动重连。
- 心跳、缓存有效期、最大连接数、异常重连和 REST 回补窗口须在实现前确认。SSE 不得持有数据库事务或 RabbitMQ 消费租约，断开和超时必须释放资源。

## 9. 数据库与迁移

- schema 变化使用版本化迁移并随应用代码提交；禁止依赖手工改库或 ORM 自动更新 schema。
- 迁移在空库和上一受支持版本上都可重复验证。破坏性变更需要兼容窗口、备份及前滚/回滚说明。
- 表、索引和约束从查询、排序、幂等、outbox 发布和 worker 条件状态更新路径反推，并通过真实 MySQL 验证。标识符、幂等键和枚举字段须使用明确的大小写敏感排序规则，不能依赖服务器默认 collation。
- MyBatis 动态 SQL 只拼装已批准的筛选和排序白名单，值参数化；导出使用范围快照和稳定排序的 Keyset 批量查询。Flyway 迁移与合成订单初始化分离，不以 MyBatis 或 ORM 自动建表代替迁移。
- Java `Instant` 按 UTC 精确到微秒存储，金额使用明确精度和小数位的 `DECIMAL`；schema 必须显式声明类型、默认值、非空、唯一约束和索引，不依赖 MySQL 隐式类型转换或宽松截断。
- 测试数据初始化与 schema 迁移分离；合成订单脚本可重复执行，初始化后订单只读。
- MyBatis 与 Flyway 的选型待 ADR 评审；具体 SQL、迁移脚本和事务参数在规格中确定。

## 10. 配置、日志与安全

- 配置通过 Spring 配置和环境变量注入；密钥、真实凭证、机器绝对路径不得提交仓库或写入镜像。
- Redis 进度缓存 key 与 RabbitMQ exchange、queue、routing key 必须由集中配置生成并按环境隔离，不得散落硬编码。
- 启动时校验必要目录、MySQL、RabbitMQ、Redis、队列拓扑和关键数值范围，错误时快速失败并给出不泄密诊断。
- 结构化日志至少可关联 `requestId`、`taskId` 和安全错误码；不得记录客户姓名、手机号、完整筛选载荷、幂等键、下载路径或文件内容。
- 用户可见错误摘要来自稳定错误分类，不直接暴露异常消息。
- 本期无认证时只允许本地受控环境使用，不得部署到公开网络。
- SIGTERM 时停止发布/领取新消息，释放 SSE 连接，并按已批准策略处理正在生成的任务；未确认业务终态的 RabbitMQ 消息不得提前确认。

## 11. 后端质量门禁

- 先按 [`testing.md`](testing.md) 编写失败测试或记录批准的覆盖缺口，再实现生产代码。
- 提交前依次通过格式化检查、静态分析、单元测试、MySQL + RabbitMQ + Redis 集成测试、契约测试、打包和产物检查。
- 使用 Maven Wrapper 和锁定插件；不得依赖全局 Maven 或本机数据库。
- 关键并发、事务、SQL、迁移、outbox、队列、进度缓存和恢复测试必须运行在隔离的 MySQL 8.4 LTS、RabbitMQ 与 Redis 8；不得用 mock repository、内存队列或 H2 替代。执行方式建议采用 Testcontainers，待测试工具基线审批后确定。
- 与具体 [`AC`](../product/acceptance-criteria.md) 或 [`SC`](../product/acceptance-criteria.md#产品成功标准) 相关的实现、测试和报告必须链接到唯一验收基线。

## 12. 评审清单

1. 分层依赖方向是否正确。
2. OpenAPI、DTO、错误码、分页和枚举是否与前端及规格一致。
3. 幂等是否由唯一约束和事务保证。
4. 任务创建与 outbox 是否同事务，dispatcher 是否可重试且容忍重复发布。
5. RabbitMQ 发布确认、消费确认、重新投递和 MySQL 条件状态更新是否避免重复执行。
6. Excel 是否流式、稳定排序、原子发布且不会泄漏临时文件或内存。
7. MySQL 权威状态、Redis 进度缓存和 SSE 是否可回补并保持单调一致。
8. 日志、错误、RabbitMQ 消息、Redis 缓存、文件名和下载路径是否避免敏感信息及路径注入。
9. 每项验收是否具有可运行测试或批准的替代验证。

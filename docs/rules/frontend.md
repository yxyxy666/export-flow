# 前端工程规则

## 文档边界与技术栈

本文只规定前端长期适用的技术栈和统一工程要求。具体页面、路由、字段、状态动作、SSE 时序和接口路径以[产品需求](../product/order-export-prd.md)、[验收基线](../product/acceptance-criteria.md)、已批准 ADR 和未来获批的功能规格为准。

- 已确认的前端选型见 [`ADR-0002`](../adr/0002-frontend-stack-and-test-scope.md)：React、TypeScript、Vite、`pnpm`、Ant Design、React Router、TanStack Query、React Hook Form + Zod；测试使用 Vitest、Testing Library 和 MSW。Node.js 使用 22 LTS 或经 ADR 修订的版本，依赖通过锁文件固定。
- 路由、服务端状态、表单、组件和 API client 分工明确；新增依赖须检查维护状态、许可、体积与现有方案的重叠。
- 前端功能仍遵守 [项目宪法](../../.specify/memory/constitution.md) 的规格审批和测试先行门禁；测试设计遵循 [`testing.md`](testing.md)，本地构建门禁已经确定，托管CI延期，见 [`build.md`](build.md)。

## 架构与状态

- 页面和组件负责展示、输入与交互，不直接拼装协议 URL 或承载隐蔽业务决策。功能用例负责流程编排；API client 集中处理请求、取消、错误归一化和协议映射；DTO 与页面 ViewModel 分离。
- 已提交查询、编辑中表单、跨页面或跨页的临时选择、服务端缓存和实时进度分别明确所有者；不得把服务端数据无理由复制进多个全局 store。
- URL 只保存适合刷新、分享与前进/后退恢复的非敏感已提交状态。进入路由时解析并规范化 query，非法值不得直接进入 API 请求。未匹配路由、渲染异常和普通请求错误分别处理。
- 异步区域区分空闲、加载、空结果、错误和成功；旧请求不得覆盖新查询，后台刷新不得清空仍可用的数据。卸载时释放无用请求、实时连接和监听器，不把页面卸载误当作已受理后台工作的取消。
- 使用 Ant Design 基础控件和设计令牌，不复制其内部实现或依赖不稳定 DOM。自定义组件须满足相同的键盘、焦点和可访问性要求。

## API、安全与展示

- API client 负责协议序列化、超时、取消和受控重试；只有明确幂等的操作才能自动重试。提交结果不明时，不得仅凭网络错误推断服务端操作成功或失败。
- 前端校验改善交互，但服务端仍必须重新验证业务边界。界面逻辑依赖稳定错误码，不依赖错误文案；协议枚举在边界集中映射，未知值不得悄悄变成另一业务状态。
- 时间按 API 的 UTC 约定解析和序列化，按产品时区展示；金额使用十进制定点字符串，不用二进制浮点进行业务计算。
- 不在 URL、浏览器长期存储、客户端日志或分析事件中存放客户信息、凭证、幂等键或完整敏感载荷。用户可见错误不得泄露堆栈、内部地址或后端异常原文。
- 下载文件名和响应头按安全规则处理；操作是否可用以最新权威状态为准，前端禁用不替代服务端检查。

## 可访问性、性能与验证

- 表单、表格、对话框和按钮使用语义化控件；键盘可操作、焦点可见且可恢复、错误与字段关联。禁用原因不得只放在 hover 提示；状态和进度不能只靠颜色表达。
- 布局适应目标视口，窄屏主要操作与行上下文仍可理解。浏览器兼容范围、最小视口和性能目标由产品或获批验证方案确定，不在本规则写单次功能阈值。
- 列表按服务端分页，不为页面展示加载完整数据集；重型非首屏能力按需加载。相同读请求尽量合并，旧响应不能覆盖新状态。
- 测试设计覆盖键盘/焦点、异步乱序、错误恢复与前后端协议边界；本期本地测试/类型检查/构建门禁见[构建规则](build.md)，托管CI延期。本期不设置浏览器端到端测试门禁，见 [`ADR-0002`](../adr/0002-frontend-stack-and-test-scope.md)。

模块按业务能力组织；共享模块只承载稳定的跨功能复用代码，不建立无边界的通用目录。命名遵循 [`naming.md`](naming.md)。

# 测试规则

- 测试按金字塔组织：纯业务单元测试优先，边界契约用集成测试覆盖，关键用户流程再使用端到端测试。
- 测试名称描述行为和条件，不描述实现细节；测试数据使用最小、可读、可重复的夹具。
- 每个缺陷先增加能复现问题的失败测试，再修改实现；修复后保留该回归测试。
- 外部服务通过稳定的 fake/mock 或测试容器隔离；不得依赖线上服务、真实密钥或不可控时间。
- 覆盖率是信号而非唯一门槛；新增分支必须有对应成功、失败和边界断言。
- 规格追踪是测试门禁：`spec.md` 中每条验收标准必须有唯一 `AC-xxx` 编号；`tasks.md` 的测试任务必须逐条列出其覆盖的 `AC-xxx`，测试用例名称、注释或元数据必须引用相同编号。
- 测试先行检查必须同时验证两类缺口：未被任何测试覆盖的验收标准，以及测试任务/用例未声明验收标准的孤立测试。发现缺口时，在实现前记录为覆盖缺口并由评审明确豁免。
